项目经理的专业语言

甘特图、WBS、RACI、风险矩阵……PMO 开口的每一个词，都是在管理一个复杂系统不失控。读懂它们，你就能看懂项目背后的管理逻辑。

2026-06-05 阅读约 12 分钟 项目管理 · PMO 术语 建议先读第一、二篇

产品经理关注的是"做什么"，项目经理关注的是"怎么按时做完"。一个功能再好，如果所有人踩点混乱、分工不清、风险没人管，最终也会延期翻车。

项目经理（PMO）的工作本质是管理不确定性——把一个混沌的目标，拆解成清晰的任务、时间和责任，让多个角色协同推进而不失控。他们的语言，是为这个目标服务的工具。

本篇的术语主题色是紫色，对应项目经理角色。你在第二篇流程图里见过他们——负责排期、跟进进度、盯上线发布。

第一层

把目标变成计划——规划语言

项目启动之后，第一件事是把模糊的目标拆成可执行的任务，并确定谁在什么时间做什么。这一层的词，是把混沌变成秩序的工具。

规划相关术语
WBS Work Breakdown Structure

工作分解结构——把一个大项目逐层拆解成可执行的最小任务单元，像树状图一样，从"完整目标"一直拆到"具体的一件事"。

「我们先把这个项目做个 WBS，把所有任务都列出来，再评估工作量。」

甘特图 Gantt Chart

用横条形式展示每个任务的开始时间、结束时间和相互依赖关系的时间规划图，一眼看出谁在什么时候做什么、有没有冲突。

「甘特图我更新了，你看一下第三周前端和后端有资源冲突。」

关键路径 Critical Path

项目中决定最短完成时间的那条任务链——链上任何一个任务延迟，整个项目都会延期。是项目经理重点盯防的对象。

「后端接口在关键路径上，这里不能延，否则前端联调就没时间了。」

依赖关系 Dependency

任务之间的先后约束——A 任务完成之后 B 才能开始。项目经理要识别所有依赖，避免"等了半天才发现前置没做"。

「前端的工作依赖后端接口文档，文档没出来前不能开工。」

缓冲时间 Buffer / Slack

排期时预留的余量时间，专门用来应对突发的延迟、返工或需求变更，避免计划一旦出现小波动就整体崩掉。

「工作量评估完 12 天，我加了 3 天缓冲，总共排 15 天。」

第二层

说清楚谁负责什么——分工语言

多人协作最容易出的问题是"以为有人管，结果没人管"。RACI 矩阵是解决这个问题的标准工具。

分工协作相关术语
RACI 矩阵 RACI Matrix

明确每项任务由谁负责、谁拍板、谁参与、谁知情的分工框架。R=执行、A=决策、C=咨询、I=告知，四个字母覆盖所有协作关系。

「我们把这个项目的 RACI 对齐一下，不然到时候扯皮。」

资源 Resource

项目所需的人力、时间和工具。"资源不够"通常指人手不足或时间紧张，是项目经理向上申请支持的理由。

「这期资源不够，后端只有一个人，两个项目同时跑肯定排不过来。」

阻塞 / 阻碍 Blocker

让任务无法继续推进的障碍，站会上每天必问"有没有 blocker"，目的是让项目经理尽快帮忙清除障碍。

「我这边有个 blocker，第三方支付接口文档还没给，卡了两天了。」

交付物 Deliverable

每个阶段结束时需要产出的具体成果，可以是文档、代码、测试报告或上线的功能，有了交付物才能明确"做完"的标准。

「这期的交付物是：接口文档、前端页面、测试报告、上线记录。」

第三层

识别和应对风险——风险管理语言

项目里总会有意外。项目经理的职责不是消灭风险——风险无法消灭——而是提前识别、评估、并准备好应对方案，让"意外"变得没那么意外。

风险管理相关术语
风险矩阵 Risk Matrix

用"发生概率"和"影响程度"两个维度评估风险等级的工具，高概率 × 高影响 = 必须立刻处理，低概率 × 低影响 = 记录备案即可。

「把所有风险放进风险矩阵里评级，优先处理红色区域的。」

应急预案 Contingency Plan

风险真的发生时的备用行动方案，提前想好"如果 X 出问题，我们就做 Y"，而不是到时候现想。

「第三方支付接口有延迟风险，应急预案是先上线积分发放，支付接入下一期。」

范围变更 Scope Change

项目进行中需求发生变动，导致工作量、时间或资源需要重新评估。项目经理必须把变更的代价明确告知所有人，而不是默默吸收。

「这个是范围变更，新增的功能要重新评估工期，不能直接加进去。」

升级 / 上报 Escalation

当项目中出现超出团队解决能力的问题时，主动向上级报告寻求支持，是负责任的表现而不是示弱。

「这个问题我们层面解决不了，需要升级到总监那边来拍板。」

第四层

跟进项目进展——过程管理语言

项目开始之后，计划就只是计划。真正的挑战在于持续追踪进度，识别偏差，及时调整。这一层的词，是项目经理每天要用的工具。

过程管理相关术语
进度报告 Status Report

定期（通常每周）汇报项目当前状态的文档，包含完成了什么、下周做什么、有什么风险或阻碍，让所有相关方保持同步。

「每周五发一份进度报告给各方，不要等到出问题才开口。」

燃尽图 Burndown Chart

展示剩余工作量随时间减少趋势的图表，理想状态是一条斜线，如果实际线高于理想线，说明进度落后需要干预。

「燃尽图显示我们已经落后两天了，下周要加快。」

看板 Kanban Board

把任务按"待办 / 进行中 / 已完成"三列可视化展示的工具，让每个人都能一眼看到整体进度和阻塞点，常用 Jira、Trello 等工具实现。

「把你的任务状态更新到看板上，不然我不知道你卡在哪了。」

复盘 / 回顾 Retrospective

项目或迭代结束后的总结会，聚焦"做得好的继续""下次改进的"两个方向，目的是让团队持续变好，不是追责。

「这期复盘最大的收获：提测前需要跑一遍冒烟测试，下期加进去。」
