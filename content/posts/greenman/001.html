职场通用术语——
和所有人说话都能听懂

不管你是前端、后端还是刚转行的新人，这些词你每天都会听到。按沟通场景分组，学一个用一个。

2026-06-05 阅读约 10 分钟 通用术语 · 沟通场景 无需任何基础

这篇文章的目标只有一个：让你在接下来的日常工作中，不管跟谁开会、在哪个群里被 @ 到，都能听懂对方在说什么。

术语很多，但这里只讲最高频的那些——不是词典，是你第一周就会遇到的词。我们按"你可能在哪个场景听到它"来分组，而不是按岗位分，因为这些词基本上所有人都会用。

每个术语都有两行：第一行是定义，第二行是一句真实会出现在工作中的话，帮你建立语感。

场景一

说需求的时候——"这个需求……"

每一个功能、每一次修改，在进入开发之前，都叫做"需求"。围绕需求产生的一系列词汇，是你开会频率最高的那类。

需求相关术语
需求 Requirement

产品或业务提出的"我们想要做什么"，是所有开发工作的起点。

「这个需求本周能排进去吗？」

PRD Product Requirements Doc

产品需求文档，产品经理写的"说明书"，描述这个功能做什么、长什么样、怎么运转。

「PRD 还没出，你先别动这块。」

迭代 Iteration / Sprint

一个固定周期（通常 1～2 周）内完成一批功能，周而复始地推进产品演进。

「这个功能放到下个迭代做吧，这期已经满了。」

优先级 Priority

决定哪个需求先做、哪个可以等，常用 P0/P1/P2 表示紧急程度，P0 最高。

「这是 P0 需求，必须本周上。」

排期 Scheduling

评估并确定各项工作的开始时间和完成时间，是项目管理的核心动作之一。

「研发这边排期多久？我这边要跟业务对齐。」

评审 Review

开发前各方对需求文档或方案的集体确认会议，避免做到一半发现理解不一致。

「明天下午三点需求评审，你们研发都要到。」

验收 Acceptance

功能开发完成后，由产品或业务方确认"做出来的和我要的一样"，通过才算交付完毕。

「你这个功能我验收完了，没问题，可以上线。」

场景二

说进度的时候——"现在到哪儿了？"

每次站会、每次项目同步，最核心的问题就是"现在做到哪了"。这一组词是描述时间节点和进度状态的。

进度时间相关术语
里程碑 Milestone

项目中具有标志性意义的时间节点，比如"需求锁定日"、"提测日"、"上线日"。

「下周五是这期的里程碑节点，必须提测。」

deadline Deadline

截止时间，过了就晚了的那个点，通常不可移动。

「这个的 deadline 是周五晚上，别拖。」

提测 Submit for QA

研发开发完成后，把功能交给测试同学开始测试，是从"开发"进入"测试"阶段的信号。

「登录模块今天提测，你们 QA 可以安排了。」

延期 Delay

没有按计划时间完成，需要推迟交付，通常需要说明原因并更新新的时间节点。

「接口对接出了问题，这期可能要延期三天。」

站会 Stand-up

每天固定时间（通常 15 分钟内）的快速同步会议，每人说三件事：昨天做了什么、今天做什么、有没有阻碍。

「早上十点站会，说一下你这边的进度。」

"提测"不是在测什么，
是在说"我做完了，轮到你了"。

场景三

说上线的时候——"什么时候能上？"

一个功能从开发完到用户真正能用，中间有一套固定的流程。这一组词描述的是这段旅程，也是前言里小李踩坑的那个区域。

一个功能的上线旅程
开发完成提测
→
测试通过UAT
→
灰度上线小范围验证
→
全量发布所有用户
上线发布相关术语
UAT User Acceptance Test

用户验收测试，上线前最后一道关卡，通常由产品或业务方模拟真实用户操作，确认没有问题。

「UAT 那边已经签字了，就等你们发布。」

灰度 Canary / Gradual Rollout

先把新功能发布给一小部分用户（比如 5%、10%），观察稳定后再逐步扩大到所有人，出问题损失小。

「先灰度 10% 的用户跑一天，没问题再全量。」

全量 Full Rollout

把功能推送给 100% 的用户，通常是灰度验证通过后的最后一步。

「灰度三天没有问题，可以全量了。」

回滚 Rollback

上线后发现严重问题，把版本退回到上一个稳定状态，相当于"撤销上线"。

「线上报错了，先回滚，我们排查原因再重新上。」

热修复 Hotfix

线上出了紧急 bug，不走常规发布流程、直接修复并上线的操作，常在半夜发生。

「支付那边有 bug，需要今晚打一个hotfix。」

发布窗口 Release Window

允许上线操作的时间段，通常避开流量高峰（如工作日白天），选在深夜或周末低峰期。

「今天的发布窗口是晚上 10 点，在那之前准备好。」

场景四

说问题的时候——"这里有个 bug……"

出了问题怎么描述它、怎么跟进它，这里的词你会在测试群、紧急群里高频出现。

问题质量相关术语
Bug Bug / Defect

程序里的缺陷或错误，导致功能表现和预期不一致。

「这里有个 bug，点击按钮没有反应。」

复现 Reproduce

按照某个步骤操作，能稳定地再次触发同一个 bug，是修复 bug 的前提。

「这个问题能复现吗？给我说一下操作步骤。」

回归 Regression Testing

修复 bug 或新版本上线后，重新测一遍之前的功能，确认新改动没有破坏已有的东西。

「这次改动影响了支付流程，需要做一轮完整的回归。」

线上问题 Production Issue

已经发布给真实用户的版本上出现的问题，比测试环境的问题严重得多，需要优先处理。

「这是线上问题，先放手头的事，优先排查。」

复盘 Postmortem / Retrospective

问题解决后的总结会，分析"为什么发生"和"下次怎么避免"，不是追责，是改进。

「这次故障我们周五开个复盘，把根因找出来。」

"回归"不是"退回去"，是"再验证一遍"。很多新人第一次听到"需要回归"会以为是被退单，其实只是让你再测一轮。

场景五

说协作的时候——"这件事谁来跟？"

一个项目涉及多个人，怎么分工、怎么对齐、怎么推进，这一组词是跨团队沟通的基础词汇。

协作流程相关术语
对齐 Align

让相关人员对某件事形成一致的理解和共识，避免各自理解不同导致做出不同方向的东西。

「上线前我们需要跟业务对齐一下，确认逻辑没有偏差。」

同步 Sync

把信息、进度、决策告知相关人，让所有人保持在同一状态，可以是会议也可以是一条消息。

「这个决定你帮我同步一下测试和产品那边。」

跟进 Follow up

对一件尚未完成的事情持续关注和推动，确保它不会因为没人管而自然消失。

「这个问题你帮我跟进一下，下周同步结果给我。」

owner Owner

某个任务、模块或问题的负责人，出了问题第一个被找的就是 owner。

「这块谁是 owner？让他来解释一下。」

拉通 Pull-through / Align All Parties

把所有相关方拉到一起开会或沟通，确保没有人被遗漏在信息传递之外，常用于跨部门协作。

「这件事比较复杂，我们先拉通一下各方再开始排期。」

联调 Integration Debug

前端和后端开发完各自的部分后，把它们连起来一起测试，解决接口对接中出现的问题。

「后端接口好了，我们可以开始联调了。」

kickoff Kickoff Meeting

项目启动会，正式宣布一个项目或迭代开始，明确目标、分工和时间节点。

「明天上午 Q3 大项目的 kickoff，请所有相关方参与。」

场景六

说环境的时候——"这是测试环境还是线上？"

同一套代码，在不同的"环境"里跑，结果可能不一样。搞清楚"现在说的是哪个环境"，能避免很多无谓的排查。

环境术语
开发环境 Dev Environment

工程师在本地或开发服务器上跑代码的环境，数据是假的，可以随意折腾。

「在开发环境上能跑通，但测试环境就挂了。」

测试环境 Test / Staging Environment

专门给测试同学使用的环境，尽量模拟线上，但数据不是真实用户的。

「测试环境上的数据是我手动插进去的，不代表线上。」

线上环境 Production Environment

真实用户在使用的那套系统，这里出了问题就是"线上事故"，优先级最高。

「千万别在线上环境上乱改，先在测试验证了再上。」

一个小经验：开会时如果不确定对方说的 bug 是哪个环境的，先问一句"是线上还是测试环境？"——这一问能省掉大量不必要的排查时间。
