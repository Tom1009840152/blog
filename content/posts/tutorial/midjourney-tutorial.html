Midjourney 使用教程
从抽卡到风格系统

Midjourney 的强项不只是“画得好看”，而是把四图探索、变体、风格参考、个性化与参数控制串成一套视觉工作流。本文以当前 V8.2 为基准，讲清官网生图、提示词、参考图、自定义种子、个人风格、版本兼容、隐私和算力。

2026-08-21 图片模型教程 阅读约 20 分钟 Midjourney · V8.2 · 风格控制

Midjourney 是一个以审美探索和图像迭代见长的生成平台。现在可以直接在官网 Create 页面创作，也仍可通过 Discord 的 /imagine 使用。根据 Midjourney 官方入门指南，使用前需要订阅；输入提示词后，系统首先生成一组 4 张候选图，再围绕其中一张继续变体、放大、扩图或编辑。

版本先行：截至本文核对日期，默认模型是 V8.2。网上大量 V6 / V7 教程中的 --q、多重提示词、Draft、Turbo、Character / Omni Reference 不能原样套用到 V8.2。先确认版本，再抄参数。

01 · 特殊机制

Midjourney 最需要先理解的五件事

SPECIAL 01
一轮四张

先探索四个方向，再选图继续；它天然是一棵决策树，不是单图问答。

SPECIAL 02
参数在末尾

参数必须放在提示词末尾，双短横线、空格和标点写错都可能失效。

SPECIAL 03
参考图分工

Image Prompt 管内容，Style Reference 管视觉，Omni 管主体，精修交给 Editor。

SPECIAL 04
版本决定能力

使用某些功能会切换模型；旧版本参数并不自动兼容当前 V8.2。

SPECIAL 05
默认公开

作品、提示词和参考图可能被他人看到；丢进回收站不等于设为私密。

还有一个常被忽略的限制：Midjourney 通常不提供公开 API，官方社区准则也禁止未经授权的脚本和第三方自动化。看到“Midjourney API”服务时，不要默认它是官方接口，更不要把主账号凭据交给来路不明的工具。

02 · 入口与第一次生成

新手优先用官网，Discord 留给命令型工作流

RECOMMENDED
Midjourney 官网

进入 Create 页面，在顶部 Imagine 输入框写提示词；设置、参考图、历史素材和编辑都集中在可视化界面里。

适合：第一次使用、参考图管理、筛选与整理作品
COMMAND FLOW
Discord Bot

在允许 Midjourney Bot 的频道或私聊中使用 /imagine，通过命令、图片 URL 和参数生成。

适合：熟悉旧工作流、团队频道、快速输入命令
登录并确认订阅

打开 midjourney.com，登录并进入 Create。官网与 Discord 的版本、速度、公开模式等设置会同步，生成前先看一眼当前状态。

先写一条短提示词

从主体、环境、媒介、光线、颜色、情绪和构图中挑最重要的内容。官方建议短而明确，不要先堆一大段操作说明。

设置画幅与版本

社媒竖图可用 --ar 4:5，横幅可用 --ar 16:9。需要锁定现行模型时，在末尾加 --v 8.2。

从四张图里选方向

不要同时修四张。先找构图最接近目标的一张，再做 Variations；方向对了才继续放大和编辑。

保存成功提示词与参考

记录版本、参数、seed、Style Reference 和最终选择路径。可复用的不是一句“神词”，而是一套可复现配置。

03 · 提示词公式

写“画面是什么”，少写“请帮我怎么做”

01主体
02环境
03媒介
04光色
05构图
06参数
a strawberry matcha latte on a dark walnut table, clear layers of matcha, milk and strawberry puree, a rainy street-corner cafe in the background, condensation on the glass, editorial food photography, muted forest green and berry red, soft overcast window light, shallow depth of field, generous negative space at the top, premium opening poster --ar 4:5 --raw --s 180 --c 8 --v 8.2

这个结构没有“帮我做一张高级海报”之类的抽象请求，而是直接描述最终画面。若要排版文字，可以在提示词里用英文双引号包住需要出现的短文案；但正式商业海报仍建议把图片和文字排版分开验收。

否定要求不要塞进自然语言长句里，使用 --no，例如 --no people, watermark, extra cups。它是在降低相关元素，不是像素级“绝对禁止”。

04 · 四图与变体

Midjourney 的核心不是第一轮，而是选择路径

01 · EXPLORE
四图探索

用较简洁的提示词寻找构图、气质和镜头方向。

02 · SELECT
选一张

优先选结构正确的图，而不是只看局部细节最精致的图。

03 · VARY
做变体

Subtle 保留更多，Strong 探索更远；Remix 可同步改提示词。

04 · FINISH
扩图与精修

Zoom / Pan 扩画布，Editor 改局部，最后再选择分辨率或放大。

使用同一个 seed 适合做对照测试，但它不是“锁住所有细节”的角色一致性按钮。V8.1 / V8.2 中相同 seed 的结果高度接近，仍可能因提示词、设置和功能变化而不同。真正要锁定主体，需要参考图和明确的文字锚点。

05 · 参考图体系

内容、风格、主体和精修，各用各的工具

IMAGE PROMPT
内容与构图参考

影响画面内容、构图、颜色与整体感觉；它是“启发”，不会精准复制。

--iw 0–3
STYLE REFERENCE
只参考视觉风格

提取颜色、媒介、纹理和光线，不负责带入原图中的人物和物体。

--sref · --sw 0–1000
OMNI REFERENCE
带入人物或物体

保持角色、产品、车辆或生物特征；目前只兼容 V7，使用时会切回 V7。

--oref · --ow 1–1000
EDITOR
精确编辑与扩画布

当目标是修改原图局部而非重新启发时使用；某些操作仍由 V6.1 管线完成。

Edit · Pan · Zoom

在官网上传图片后，可以把同一素材拖到不同参考槽位；需要多轮使用时用锁定功能固定在 Imagine 输入框。Discord 中，Image Prompt 的图片 URL 放在提示词开头，Style / Omni 则使用末尾参数。

[产品参考图 → Image Prompt] [杂志参考图 → Style Reference] a compact espresso machine on a limestone counter, three-quarter view, morning cafe interior, clean product silhouette --iw 1.4 --sw 180 --ar 3:2 --v 8.2

不要把 Style Reference 当成角色参考。如果你希望保留同一人物或产品，Style Reference 只会借走“怎么画”，不会可靠保留“画的是谁”。另外，上传外部图片前必须拥有必要的使用权。

06 · 参数速查

参数必须放在末尾，而且不能带多余标点

V8.2 常用参数
画幅--ar 4:5改变宽高比。V8.2 最大可到 14:1；HD 图最大 4:1。
原始模式--raw减少 Midjourney 的默认审美加工，提高对提示词的直接遵循。
风格化--s 100控制 Midjourney 审美介入程度。低值更听描述，高值更强调艺术处理。
变化度--c 0–100提高四张候选之间的差异。找方向时提高，收敛方案时降低。
怪异度--w 0–3000增加非典型、实验性结果；与高 stylize 同时使用时更难预测。
排除--no text, logo降低不希望出现元素的权重。多个元素用逗号分隔。
随机种--seed 12345用于对照实验和复现近似起点，不等于锁定人物或画面。
平铺--tile生成可无缝重复的纹样，适合包装、壁纸和材质。
版本--v 8.2显式指定模型，避免设置变化或旧提示词引发误判。
分辨率--sd / --hdV8.1 / V8.2 可直接生成约 1024px 或 2048px；HD 消耗更多 GPU 时间。

正确：coffee poster --ar 4:5 --s 200。常见错误包括：提示词与 -- 之间没空格、写成 - - ar、参数后带逗号、参数后又继续写描述。

08 · 种子与风格系统

能自定义 Seed，也能“炼风格”，但不是一回事

你记对了
Seed 可以自己指定

使用 --seed 整数，范围是 0–4294967295。它固定生成开始时的随机噪声，适合做提示词 A/B 测试。

需要纠正
Seed 不能保存风格

Seed 不是模型、预设或角色档案，不能收藏某种画风，也不保证跨会话、版本和设置得到相同图片。

你记对了
风格可以训练与分享

Personalization、Moodboard 和 Style Creator 都能形成可复用代码；但训练方式、参数和分享语义不同。

根据 Midjourney 官方 Seeds 文档，V8.X 使用相同 seed 时结果约 99% 接近，但 Seed 对最终图片的影响最弱。提示词、模型版本、参数或设置稍有改变，都可能让结果明显变化。因此它最适合做控制变量，不适合充当“风格密码”。

第一次：建立基准 a ceramic fox on a museum pedestal, soft studio light --seed 20260821 --ar 4:5 --v 8.2 第二次：只改一个变量，观察材质变化 a glass fox on a museum pedestal, soft studio light --seed 20260821 --ar 4:5 --v 8.2
四种容易混淆的“可复用控制”
Seed--seed 12345固定随机噪声起点，用于测试与近似复现；不能保存风格、角色或具体外观。
个性化--p code通过不断选择、点赞图片，让 Midjourney 学习你的宽泛审美偏好；可建立多个 Profile。
情绪板--p code主动放入一组项目参考图，形成更明确的品牌、专题或系列视觉；更新素材会产生新版本代码。
风格代码--sref code用 Style Creator 的多轮选择收敛到自定义 Style Reference Code，或从 Style Explorer 发现社区代码。

四条“炼风格”路线，怎么选

◐
Style Reference

已有一张明确范例时最快：直接上传图片，只借颜色、媒介、纹理与光线；用 --sw 控制强度。

▦
Moodboard

自己挑一组图片建立项目审美，适合品牌、专题与系列视觉。它使用 --p，不能与 --sw 同用。

✦
Personalization

通过成对选择与点赞训练审美档案，适合“我长期喜欢什么”；用 --p，用 --s 控制介入强度。

#
Style Creator

连续选择更喜欢的样图，同时利用“选中与未选中”收敛风格，生成自定义 --sref 代码。

⌁
Raw

当默认审美压过产品 Brief 时，用 Raw 减少自动美化，让描述获得更多控制权。

◎
Niji 7

面向动漫与东方插画的独立模型，理解更字面，线条与局部一致性更突出。

实操上，Style Reference 解决“这次像什么”，Moodboard 解决“这个项目整体像什么”，Personalization 解决“我长期喜欢什么”，Style Creator 则通过一轮轮选择寻找可复用的风格代码。官方说明 Style Creator 的风格通常在 5–10 轮后趋于稳定，10–15 轮主要增加细节；每轮预览都会消耗 GPU 时间，而且当前预览使用 V7。

真的能分享，但分享对象要说清楚

风格分享速查
  • Personalization：分享某次提示词中的 --p code，别人可以复用那一版个性化效果；Profile 继续学习后会产生新代码，旧代码仍是旧快照。
  • Moodboard：分享情绪板链接可让别人看到图片并使用持续更新的最新版；分享 --p code 则是固定版本的快照。
  • Style Creator：分享 --sref 数字代码，别人粘到提示词末尾即可使用。Style Explorer 也能浏览、收藏和尝试社区热门代码。
  • Seed：数字当然也能发给别人，但它只是随机起点；只有模型、提示词和其他设置也一致时，才适合做近似复现实验。
分享个人审美快照 a quiet reading room at dawn --p abc123 --s 250 --v 8.2 分享自定义 Style Creator 风格 a quiet reading room at dawn --sref 1234567890 --sw 180 --v 8.2

“炼风格”不是微调模型。这些功能是在 Midjourney 现有模型上学习或调用审美偏好，不会得到可下载的模型权重，也不能把一组上传图片直接转换成专属数字 --sref。上传图组建立项目风格，应使用 Moodboard。

不要一开始同时叠满 Personalization、Moodboard、Style Code 和高 Stylize：先锁定 seed 做单变量 A/B 测试，再逐层组合。风格代码在不同模型版本中可能呈现不同效果，分享时最好一起注明 版本、完整参数和一张示例图。

09 · 算力与隐私

Fast、Relax、Turbo，以及“公开优先”的默认规则

生成速度与成本逻辑
Fast--fast消耗订阅内每月 Fast GPU 时间；额度在续订时刷新，未用完不会结转。
Relax--relax图片任务不消耗 Fast 时间，但需排队；仅 Standard、Pro、Mega 计划可用。
Turbo--turbo最多约比 Fast 快 4 倍，同时消耗双倍 Fast 时间；当前 V8.1 / V8.2 不支持。
HD--hdV8.2 一组四张约消耗 1.3 GPU 分钟，SD 约 0.8 分钟；先 SD 定方向更划算。
Omni--orefV7 Omni Reference 通常消耗约 2 倍 GPU 时间，且不兼容 Fast 模式。

默认公开：Midjourney 是 open-by-default 社区，作品可能出现在 Explore。Stealth 仅面向 Pro / Mega；即使开启 Stealth，在公开 Discord 频道生成的内容仍会被频道成员看到。需要完整隐私时，应同时使用 Stealth，并在官网 Create、Bot 私聊或私人服务器中创作。

Stealth 不会自动把过去的公开作品全部改成私密；删除或丢进回收站也不等同于隐藏，作品仍可能通过 Explore、排名、Job ID 或链接找到。商业机密、未发布产品和客户素材，在上传前就要先确认计划与公开设置。

10 · 稳定出图

常见问题与一套可复用工作流

提示词很长，画面却更乱
删掉对话式说明和同义词堆叠，只保留能在画面里被看见的名词与形容词；精确数量要写数字。
风格参考带不住人物
这是工具选错。Style Reference 只负责视觉风格；人物或物体用 Omni Reference（会切到 V7），精确修改用 Editor。
照着教程写 --q 没效果
先看版本。V8.1 / V8.2 不支持 Quality 参数；旧 V6 / V7 教程需要按官方兼容表重写。
四张图差异太小
提高 --c，减少过细限制；找到方向后再把 chaos 降低，用变体收敛。
产品外形不稳定
使用清晰、裁切接近目标画幅的 Image Prompt，明确只参考结构和材质；必要时用 V7 Omni Reference，并降低高 stylize 的竞争。
扩图后清晰度下降
V8.2 的 Pan / Zoom / Editor 会走 V6.1 并把 HD 结果降到 SD。编辑完成后再执行放大，不要反复先放大再扩图。

点击生成前，最后核对

✓已确认当前版本，旧教程里的参数和参考机制没有直接照搬。
✓提示词描述最终画面，主体、环境、媒介、光色与构图没有相互冲突。
✓全部参数位于提示词末尾，双短横线、空格和值的格式正确。
✓Image Prompt、Style Reference、Omni Reference 与 Editor 已按职责选择。
✓先用 SD / Fast 或 Relax 探索方向，确认后才投入 HD 与精修成本。
✓商业或私人内容已检查 Stealth、生成位置与历史作品可见性。
✓保存最终提示词、版本、参数、seed、参考图和选择路径，形成可复用资产。
