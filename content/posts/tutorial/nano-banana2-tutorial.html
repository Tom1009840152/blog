Nano Banana 2 使用教程
速度、知识与一致性，一次讲清

Nano Banana 2 把 Pro 级的知识理解、文字能力和主体一致性放进 Flash 速度里。本文从 Gemini 对话式创作出发，讲清提示词、参考图、信息图、多角色叙事和 API 参数。

2026-08-21 教程系列 · 第四篇 阅读约 16 分钟 Gemini · 图片生成 · 对话编辑

Nano Banana 2 的正式模型名是 Gemini 3.1 Flash Image，API 模型代码为 gemini-3.1-flash-image。Google 将它定位为兼顾速度、质量和规模化生产的通用图片模型：既能从文字生成，也能结合图片参考进行对话式编辑。

根据 Google 官方发布，它继承了 Nano Banana Pro 的世界知识、推理与创意控制，同时保留 Flash 系列的快速迭代。对于大多数日常生图任务，关键变化不是“再多一种画风”，而是更快地得到文字正确、信息可靠、主体不乱的可用结果。

01 · 核心升级

四个数字，先理解 Nano Banana 2 的边界

5
角色一致性

官方称单个工作流中最多保持 5 个角色的相貌一致。

14
对象保真

最多保持 14 个输入对象的特征，适合复杂组合与叙事。

4K
生产分辨率

支持从 512px 到 4K，并可按交付场景选择多种画幅。

Flash
快速迭代

面向低延迟和高频编辑，适合反复调整而不是一次抽卡。

能力层面还包括：实时搜索带来的世界知识辅助、清晰文字生成、图片内翻译与本地化、复杂指令遵循、信息图和数据可视化，以及更丰富的光影、材质和细节。

Nano Banana 2 不是 Nano Banana Pro 的简单替代。Google 的建议是：日常生成、快速修改与规模化任务优先用 2；极高保真、最高事实精度和特别复杂的创意控制，再考虑 Pro。

03 · 第一次生成

按这六步完成一轮可控创作

说清最终交付物

先写“4:5 小红书封面”“16:9 课程信息图”或“电商详情页产品拆解图”。交付物比泛泛的风格词更能确定布局。

决定是否需要实时信息

真实地点、当日天气、现有产品或近期事件需要搜索辅助；纯虚构创作则不必让外部资料干扰风格。

上传最小参考组合

角色任务先给清晰正面参考，产品任务给主体与标签图，风格参考和内容参考分开说明职责。

写主体、构图与文字

给每个角色或物体命名，明确位置、动作、景别和层级；图片内文案放进引号，并指定语言与排版区域。

补充不可变项

告诉模型哪些身份、服装、产品结构、标签、数据、镜头和文字必须保持，哪些内容不能新增。

低成本预览，再提高分辨率

先在默认或较低分辨率确认构图与文字，方向稳定后再输出 2K / 4K。分辨率不能修复错误的设计决策。

04 · 提示词公式

把“想要一张图”改写成可执行 Brief

01交付物
02事实依据
03主体内容
04构图风格
05精确文字
06约束检查
【交付物】 制作一张 9:16 竖版“杭州西湖一日游”信息图，用于手机端阅读。 【事实依据】 先搜索并核对西湖主要景点的真实位置关系；不要编造开放时间、票价或交通信息。无法确认的数据不要写进图里。 【内容与构图】 顶部是标题；中部是一条从早到晚的路线，依次展示断桥、曲院风荷、苏堤和雷峰塔；每个站点配一个小插画与一句短说明；底部保留注意事项区域。使用清晰箭头连接，阅读方向从上到下。 【视觉风格】 现代旅行杂志信息图，宋画配色，米白纸张纹理，青绿山水元素，信息层级清楚，适合手机屏幕。 【画面文字｜逐字照抄】 主标题：“西湖一日慢游路线” 时间标签：“清晨”“上午”“午后”“傍晚” 【约束】 所有中文清晰可读，只出现一次；地图关系必须合理；不要添加未经确认的数字，不要水印，不要二维码，不要额外英文。

Nano Banana 2 能调用实时搜索来理解具体对象，但“搜索过”不代表“事实天然正确”。最稳的写法是同时规定查什么、哪些内容不得猜、哪些数据必须省略，生成后再单独核对事实和文字。

05 · 对话式编辑

每轮只改一层，避免整张图越修越乱

Nano Banana 2 的速度优势很适合对话式迭代，但编辑指令仍要把变化项与不可变项分开。最有效的短句通常不是“优化一下”，而是“只调整标题区高度，人物、背景、配色和全部文字保持不变”。

本轮允许改变
  • 把标题区高度增加约 15%
  • 让主标题与副标题拉开层级
  • 将标题整体左对齐
→
本轮必须保持
  • 正文内容和所有文字不变
  • 人物、产品、背景和配色不变
  • 画幅、裁切与插画风格不变

建议按“结构 → 主体 → 文字 → 风格 → 细节”的顺序修改。结构还没稳定时先别抠材质；文字还没核对时先别输出 4K。

06 · 多主体一致性

5 个角色、14 个对象，不等于一次全部塞满

官方给出的上限适合复杂工作流，但想让系列图稳定，关键依然是给每个主体建立唯一身份。角色要有名字和固定特征，物体要有编号和用途，参考图要明确“只参考什么”。

ANCHOR
建立身份锚点

先生成或上传角色设定页，固定脸、发型、服装、体型、配色和标志性物件。

NAME
给主体命名

使用“角色 A / 小岚”“产品 B / 红色相机”等稳定称呼，不要每轮换一种描述。

RESTATE
每轮重申不变项

切换姿势、场景或镜头时，再次写明身份与服装保持，避免长对话逐步漂移。

【六格故事任务】 使用参考图中的三位角色，分别命名为小岚、阿禾、团子。生成 6 张独立的 16:9 画面，讲述他们一起搭树屋的故事，每次只输出一张。 每张图都必须保持三人的脸、发型、体型、服装颜色和身份一致；每个角色在单张图片中只能出现一次。允许改变表情、动作、机位和景别。 第 1 张：三人在森林空地查看设计草图，中景，轻松的清晨光线。不要文字，不要新增角色。

07 · 信息图与知识视觉

最值得尝试的，不只是漂亮照片

📚
百科与知识长图

先把主题拆成章节与事实清单，再规定阅读顺序、标签和图解方式。

🏯
古文可视化

把段落拆成地点、人物、意象和事件，区分原文、释义与视觉演绎。

📈
财报与数据图

只使用已核对的数据，明确图表类型、单位与时间范围，生成后逐项验算。

🧭
旅行攻略

利用真实地点知识辅助路线，再人工确认距离、营业时间和交通信息。

⚙️
机制与产品拆解

指定部件名称、相对位置、连接关系和标注方式，适合原理说明与爆炸图。

🏙️
3D 等距城市卡

统一相机角度、地标、天气、时间与材质，适合制作系列城市内容。

知识视觉需要双重验收：第一遍看事实、数据和文字是否正确；第二遍再看构图、层级和美感。视觉上很像信息图，不代表信息真的成立。

08 · API 进阶

模型代码、画幅和分辨率怎么设置

当前 Gemini 3.1 Flash Image 模型页列出的模型代码是 gemini-3.1-flash-image。它接受文字、图片或 PDF 输入，并输出图片和文字；图片生成、搜索辅助与思考能力均受支持。

Nano Banana 2 API 参数速查
模型gemini-3.1-flash-imageNano Banana 2 的 API 模型代码，适合作为通用图片生成与编辑默认选项。
分辨率0.5K / 1K / 2K / 4K默认 1K。先低分辨率确认方向，再按交付需求输出 2K 或 4K；参数中的 K 必须大写。
常用画幅1:1 / 4:5 / 9:16 / 16:9 / 21:9覆盖方图、社媒竖图、手机全屏、视频横图和超宽背景。
极端画幅1:4 / 4:1 / 1:8 / 8:1适合长条信息、横幅和特殊媒介；先确认承载页面是否真的支持。
搜索辅助Image Search Grounding可结合文字和图片搜索结果，用实时网络信息帮助生成具体对象与知识视觉。
默认输出text + image可以把响应格式限定为图片，或同时返回说明文字与图片。
from google import genai client = genai.Client() interaction = client.interactions.create( model="gemini-3.1-flash-image", input="制作一张 16:9 的现代园林等距摄影图，不要文字", response_format={ "type": "image", "aspect_ratio": "16:9", "image_size": "2K", }, )

代码只展示最小参数组合，返回图片的保存与异常处理请跟随 Google 官方图片生成文档。模型状态、价格、配额和 SDK 接口可能更新，正式接入前应再次核对。

09 · 稳定出图

常见问题与生成前检查

事实看着像但不对
明确要求先搜索和核对；关键数据由你提供；禁止模型猜测。生成后把文字和数字单独抄出来逐项验证。
中文太密集
减少单张图的信息量，分成标题、标签和短说明三级；长段正文交给排版工具，不要全部烘焙进图片。
系列角色漂移
先做角色设定页，给角色固定名称，每张图重复身份与服装锚点，并一次只生成一个场景。
参考物体混淆
为每个对象编号并写唯一职责，例如“对象 B 只参考杯型，不参考背景”；冲突时先减少参考图。
编辑越改越乱
回到最近满意版本，一轮只改一个层级；每次重申所有不可变项，不要在同一轮同时换人物、构图和风格。
4K 仍然不好看
高分辨率只增加输出规格，不能替代清晰 Brief。先在 1K 修正构图、文字和主体，再提高到 2K / 4K。

点击生成前，最后核对

✓已经根据任务选择 Nano Banana 2，确实需要最高精度时才升级 Pro。
✓提示词写明交付物、画幅、阅读场景和信息层级。
✓每个角色和对象都有固定名称、特征与参考职责。
✓所有图片内文字已经校对，并用引号逐字给出。
✓需要实时信息时写明搜索与核对要求，不允许模型猜测关键数据。
✓编辑任务已分开写清本轮允许改变和必须保持的内容。
✓发布前人工复核事实、数字、文字、商标与来源；了解生成图片含 SynthID 标记。
