文本域评测集

通用方法论：如何构建文本域评测集

文本域的评测集构建，是整个多模态体系的地基。文本输出相对可解释、可对比，但"什么是好的文本输出"往往没有唯一答案——这是文本评测集设计的核心挑战。

文本域评测集的四类构成
🥇

黄金用例（Golden Set）

人工精标的输入-输出对，每条都有明确的"为什么这是好输出"注释。是回归测试的锚点。数量不需多，20-50 条高质量黄金用例胜过 500 条随机样本。

⚡

对比用例（Contrastive Set）

每条包含同一输入的"好版本"与"坏版本"，坏版本对应特定失败模式（幻觉、格式错误、风格偏离）。专门用于训练和校准 LLM-judge 的判别能力。

🎯

边界用例（Edge Set）

歧义输入、极短/极长输入、多语言混合、矛盾约束（"要简洁但要覆盖所有卖点"）。专门测试模型的降级能力和不确定性处理。

🔁

线上反哺用例（Production Set）

从真实用户请求中采样，经过脱敏和标注后纳入测试集。是测试集保持与真实分布同步的唯一可靠手段，每月至少补充一次。

文本域评测集的核心设计原则，是每条用例必须绑定明确的评测维度和通过标准。一条用例如果只有输入和期望输出，没有说明"为什么这个输出是对的"，那它在后续维护时会迅速腐烂——换了评测模型或换了人工标注员，可能得出完全不同的结论。

文本域用例的标准格式
# 文本域测试用例标准格式（以脚本生成为例） { "id": "script_001", "input": { "product": "某面霜，SPF30+，72h 保湿，主打敏感肌", "target_audience": "25-35 岁都市女性", "duration": 30, # 目标视频时长（秒） "platform": "抖音" }, "expected_output": { "reference": "..." }, # 参考输出（非唯一正解） "pass_criteria": [ # ← 这是关键：明确通过标准 { "dim": "fact_accuracy", "rule": "所有功效声明必须在输入中有来源", "method": "NLI" }, { "dim": "compliance", "rule": "不含平台违禁词", "method": "rule" }, { "dim": "length", "rule": "字数在 100-130 之间（30s 语速）", "method": "rule" }, { "dim": "narrative_arc", "rule": "包含钩子/痛点/解决方案/CTA四段", "method": "llm_judge" } ], "failure_modes": [ # 已知失败模式，方便快速定位 "夸大功效（如'根治敏感'）", "遗漏 SPF 卖点", "CTA 缺失或出现在开头" ] }

💡 文本评测集的规模建议：黄金集 30-80 条（精），边界集 50-100 条（广），对比集 50-100 对（深），线上反哺集每月 30-50 条（新）。总量控制在 300 条以内，优先保证每条用例的质量和标注的准确性。测试集越大不一定越好——维护成本会把你拖垮。

视觉域评测集

通用方法论：如何构建视觉域评测集

视觉域的评测集构建，比文本域难一个量级。难点不只在于"好的视觉"更难定义，而在于标注成本极高、自动化工具覆盖有限、且评测结果依赖评估者的领域专业度。

视觉域评测的三类任务
🖼️

单帧评测

对静态帧（图片或视频截帧）做评测。工具链相对成熟：美感打分模型、目标检测、OCR、色差计算。是视觉评测的入门级。

🎞️

时序评测

跨帧的一致性、流畅度、节奏感。需要视频级别的工具：光流分析、帧间特征相似度、动作识别。这是区分视频评测与图片评测的核心维度。

🔀

跨模态对齐评测

视觉输出与文本描述（分镜/脚本）的对齐程度。需要 VQA 模型或 CLIP 类模型。是多模态流水线特有的维度，纯视觉工具无法覆盖。

视觉域评测集的构建，最关键的一步是建立参考素材库（Reference Asset Library）——它是所有客观指标的计算基准。没有可靠的参考，颜色还原率、质地相似度这些指标就无从计算。

参考素材库的构建规范
📸

产品参考图（静态）

标准光源下的产品棚拍，覆盖正面、侧面、包装细节。必须是未经修图的原始文件（RAW 或无损 TIFF），用于颜色基准提取。宣传图不可用作基准。

🎬

产品参考视频（动态）

专业拍摄的质地展示视频：挤出、涂抹、流动、成型等关键动作的慢动作素材。这是质地真实性评测的唯一可信基准。

🏷️

标注元数据

每个参考素材附带结构化标注：色号（L*a*b* 值）、质地类型、光泽等级、品类标签。是自动化评测能够运行的前提。

❌

负样本库（Failure Cases）

已知的生成失败案例：颜色偏差超标、logo 变形、质地失真、人脸不一致。用于校准自动化阈值，也是 LLM-judge 的训练数据。

视觉域核心评测维度与工具链
评测维度工具 / 方法输出指标自动化程度
颜色准确性 L*a*b* 色差（ΔE 计算） ΔE 值（<3 合格，>5 警告） 全自动
Logo / 文字识别 OCR + 字符串匹配 识别准确率 / 变形检测 全自动
帧间产品一致性 DINO-v2 特征余弦相似度 帧对相似度（阈值 0.85） 全自动

⚠️ 视觉评测集的最大陷阱：用品牌方提供的精修宣传图作为颜色和质地的参考基准。精修图往往经过颜色校正和质地美化，会导致你的评测标准比真实产品更高——用 AI 生成的画面去接近一个本身就"失真"的参考，是个死局。必须用专业实拍作为基准。

文本评测集衡量"说对了没有"，
视觉评测集衡量"看真实了没有"——
两者都要，且构建逻辑完全不同。

场景落地

以电商信息流为例：把方法论装进五节点流水线

方法论讲完了，现在进入具体场景。电商信息流素材生成是一条横跨文本域和视觉域的五节点工作流——前三步（输入解析、创意分析、脚本生成）在文本域，后两步（分镜生成、视频生成）进入视觉域。

五节点工作流与模态分布
① 用户输入产品信息、受众、诉求
→
② 创意分析卖点拆解 · 钩子设计
→
③ 脚本生成台词 · 节奏 · 情感弧
→
④ 分镜生成画面描述 · 运镜 · 转场
→
⑤ 视频生成画面 · 音频 · 合成

①②③ 适用文本域评测集方法论；④ 是跨模态桥梁节点（文本描述 → 视觉意图），需要同时运用两套方法；⑤ 适用视觉域评测集方法论，且复杂度最高——视频里那管膏体的质地，是检验整个系统的最终裁判。

逐节点评测

逐节点拆解：测什么、怎么测

①
用户输入解析
文本域 · 信息提取

用户输入通常是非结构化的：一段产品描述、一些关键词、甚至只是竞品链接。这一步的核心任务是把模糊输入转化为后续节点可消费的结构化信息。评测重点是提取准确性和信息完整度。

核心卖点提取召回率从原始输入里挖出多少卖点
对照人工标注的"黄金卖点列表"，计算 LLM 提取的召回率。关注遗漏率——漏掉一个差异化卖点可能导致整条素材失去核心价值。
规则+人标
受众定位准确率目标人群画像是否匹配
验证 Agent 识别的目标受众（年龄段、消费能力、使用场景）是否与品牌方提供的定向信息一致。用枚举型指标衡量，结构化输出便于自动化校验。
自动
产品属性结构化完整度颜色、规格、成分等关键属性
对于美妆、食品等强属性类目，产品的具体参数（颜色号、SPF 值、成分表关键词）必须被准确提取，后续视觉生成会直接依赖这些信息。
Schema 校验
歧义识别率面对模糊输入时是否主动澄清
当输入信息不足以支撑后续生成时（如"做个好看的视频"），Agent 是否能识别歧义并向用户提问，而不是基于假设强行推进。
LLM-judge
②
创意分析
文本域 · 策略生成

创意分析是整条流水线的"策略大脑"——它决定了视频的情感基调、叙事角度和钩子形式。这一步的质量决定了最终素材能否吸引目标受众。评测难点在于"好的创意"本身就是主观判断，需要 LLM-judge 和人工评审结合。

卖点与钩子的匹配度钩子是否真正服务于核心卖点
分析钩子设计（开头 3 秒的吸引力设计）是否与产品的差异化卖点直接相关，而非通用套路。用 LLM-judge 打分，要求给出具体理由。
LLM-judge
受众共鸣度创意角度是否击中目标人群痛点
对照目标受众画像，评估创意策略的情感共鸣预期。例如面向宝妈群体的护肤品，创意角度应聚焦时间效率和安全性，而非"精英生活方式"叙事。
人工审核
品牌调性一致性是否符合品牌 ToneOfVoice 规范
对于有明确品牌手册的品牌方，验证创意分析的情感基调、用词倾向、禁忌表达是否合规。可以把品牌规范文档作为 judge prompt 的 context 注入。
LLM + 规则
差异化程度相似输入下的创意多样性
对同一产品生成多次创意分析，计算输出的语义多样性（embedding 距离）。过低的多样性意味着 Agent 在走"安全路线"，无法提供真正的创意价值。
Embedding 距离
③
脚本生成
文本域 · 核心内容

脚本是视频的骨架，也是文本域最复杂的评测对象。它需要同时满足：信息准确（不能有虚假产品声明）、情感节奏（开头钩子 → 中段建立需求 → 结尾行动号召）、平台规范（无违禁词、符合投放平台的内容政策）。

事实准确性台词中的产品声明是否属实
这是电商场景的红线指标。每一个功效声明（"72小时保湿"、"SPF50+"）都必须能在用户输入的产品信息中找到来源。用 NLI 模型检测声明与产品文档的蕴含关系。
NLI 模型
叙事节奏结构分情感弧线是否符合信息流逻辑
按"钩子（0-3s）→ 建立痛点（3-8s）→ 产品解决方案（8-20s）→ 社会证明（20-25s）→ CTA（25-30s）"的结构框架，检验脚本各段是否到位。
LLM-judge
违禁词 / 违规声明检测平台合规是上线前置条件
维护平台违禁词表（极限用词、医疗声明、虚假对比等），做全文扫描。分平台维护：抖音、小红书、天猫的违规边界不同。这是唯一需要 100% 通过才能继续的检查点。
规则字典
时长适配度台词密度是否匹配目标视频时长
根据目标视频时长（15s / 30s / 60s）和正常语速（每分钟约 240 字），估算台词字数是否合理。过长或过短都会导致后续视频生成的画音比例失调。
字数计算
与创意分析的一致性脚本是否忠实执行了上游策略
跨节点一致性检验：脚本的情感基调、主打卖点、钩子形式是否与创意分析阶段的策略决策保持一致。用 LLM 对比两个输出的语义对齐度。
LLM 对比
④
分镜生成
文本→视觉 · 跨模态桥梁

分镜是这条流水线里最关键的跨模态节点：它以文字形式描述视觉画面。分镜的质量直接决定视频生成的上限——一个描述不清产品色号的分镜，无论视频模型多强，都无法还原真实的产品颜色。

视觉可实现性描述是否能被视频模型理解并执行
检测过于抽象或矛盾的视觉描述（"同时展示产品的内外部"、"镜头从无限远处拉近到分子级别"）。可用专门训练的分类器，或对视频生成结果的还原度做反向验证。
混合
产品视觉规格完整度关键视觉属性是否写入分镜描述
强制检查清单：产品颜色（精确到色号）、包装形态、关键 logo 位置、使用场景道具是否都出现在分镜文本中。缺失的视觉规格是后续产品一致性问题的直接根因。
规则核查
分镜节奏与脚本节奏对齐画面切换节奏是否匹配台词节拍
校验每个分镜的估计时长之和是否等于脚本台词时长，以及高强度情感时刻（CTA、痛点场景）是否配有相应的特写 / 强调镜头。
LLM-judge
人物/模特描述一致性同一视频内角色形象是否统一
若视频包含人物，检查各分镜中对同一人物的描述是否一致（肤色、发型、年龄段、服装风格）。前后不一致的描述会导致视频生成中出现"换人"现象。
字符串一致性
运镜合理性镜头语言是否符合产品品类惯例
美妆类产品的惯用镜头（微距特写质地、45°侧拍涂抹过程），与食品类（俯拍摆盘、浇淋慢镜）截然不同。按品类维护镜头语言规范，LLM 对照打分。
LLM + 规范
⑤
视频生成
视觉域 · 最终输出

这是整条流水线评测复杂度最高的环节。视频是多维度信息的叠加体——画面美感、声音节奏、产品真实性、人物一致性缺一不可。这里的大多数指标都需要计算机视觉模型或专业人工评审。

整体画面美感视觉吸引力 · 构图 · 色彩
用训练在人类审美偏好数据上的打分模型（如 LAION Aesthetics Score 或自训练模型）对关键帧打分，取均值。同时关注方差——帧间美感落差过大会导致视觉体验割裂。
Vision 模型
产品颜色还原准确率生成的产品颜色是否与真实色号一致
从真实产品图片提取参考颜色（L*a*b* 色彩空间），在生成视频的产品区域做 ROI 采样，计算 ΔE 色差值。ΔE < 3 为可接受，ΔE > 5 需要人工确认。
CV + 色差算法
产品质地真实性膏体、粉质、液体的物理特性还原
电商场景最难评测的维度。详见下一节的专项拆解。核心手段是：参考真实产品的物理属性（粘稠度、光泽度、流动性），与生成视频中的质地表现做多维度对比。
Vision + 人工
产品 logo / 包装准确率品牌标识是否清晰且准确
检测视频中产品包装的 logo 是否可辨识、是否变形、是否出现拼写错误（AI 生成最常见的失败模式）。用 OCR + logo 相似度模型双重验证。
OCR + 相似度
帧间产品一致性同一产品在视频中各帧的外观稳定性
提取所有包含产品的帧，计算产品区域的 DINO-v2 特征向量，计算帧间余弦相似度。低于阈值（如 0.85）的帧对标记为一致性失败，可能表现为产品"跳变"或"变形"。
DINO-v2 相似度
人物面部一致性模特在视频各帧中是否为同一人
用人脸识别模型（如 InsightFace）对所有含人脸的帧提取 embedding，计算帧间余弦相似度。阈值建议 0.7（同一人）。检测到"换人帧"时精确记录时间戳，便于定位。
人脸识别
音画同步度台词时序与画面动作是否对齐
提取 ASR 识别的台词时间轴，与分镜设计的时长分配对比，计算关键节点（CTA 时刻、产品展示切入点）的时序误差。误差超过 1.5 秒需要人工核查。
ASR + 时序对比
使用场景真实感使用场景是否符合产品使用逻辑
验证视频中的使用场景是否合理（洁面产品出现在浴室、防晒产品出现在户外），以及使用动作是否符合产品使用方式（洗发水的揉搓方式、眼影的涂抹路径）。
人工审核

质地评测专项

最难的那道题：产品质地真实性评测

质地评测是整个评测体系里最复杂、最无法完全自动化的维度——也是电商场景中最影响购买决策的视觉信号。消费者对"这个膏体看起来是不是滋润的"、"这个粉是细腻还是粗糙的"极度敏感，任何失真都会损害品牌可信度。

按产品品类的质地属性分类
💄

膏体类（唇膏 · 面霜 · 眼霜）

关键属性：光泽度（哑光/亮面/果冻质感）、拉丝性、流动性、挤出时的形变方式。参考标准：产品实拍的慢动作镜头。

✨

粉质类（腮红 · 眼影 · 粉底）

关键属性：粉质细腻度、哑光/珠光分布、落粉量。错误案例：珠光眼影被生成为纯哑光质地，会让消费者认为产品无光泽感。

💧

液体类（精华 · 水乳 · 安瓶）

关键属性：流动性（稀薄/粘稠/凝胶状）、透明度、滴落时的表面张力表现。高粘度精华被生成成水样流动是常见失真。

🫧

泡沫 / 乳化类（洗面奶 · 沐浴露）

关键属性：起泡丰富度、泡沫细腻程度、乳化后的颜色变化。丰富蓬松的泡沫传递"清洁力强"的信号，这一点消费者高度感知。

质地评测的方法论需要分两层：客观层（可量化的物理特征）和主观层（人类感知的"质感"印象）。两层评测缺一不可——客观指标覆盖不了"看起来高级"这样的主观感受，而主观评估又无法规模化。

质地评测两层方法论
🔬

客观层：计算机视觉指标

光泽度：提取产品区域的高光分布，计算高光像素比例和亮度分布
流动性：在包含质地倾倒/挤出的片段中，用光流算法估计质地运动速度
细腻度：对产品特写帧做频率分析，粗颗粒粉质的高频成分明显更高
透明度：检测产品区域的透射率（背景是否透过产品可见）

👁️

主观层：专业人工评分

质感还原分（1-5）：对照真实产品实拍，评估质地视觉还原程度
品类认知分（1-5）：仅看视频，判断这个质地属于哪个产品品类
购买意愿影响：该质地表现是否会促进或阻碍购买决策
建立打分者资质：要求评分者具有美妆行业背景或受过专项培训

# 质地评测：光泽度 + 流动性计算示例 import cv2 import numpy as np def measure_glossiness(frame, product_mask): """ 计算产品区域的光泽度分数 参数：产品区域 mask（二值图） 返回：0-1 光泽度分数（越高越亮面/越有光泽） """ roi = cv2.bitwise_and(frame, frame, mask=product_mask) hsv = cv2.cvtColor(roi, cv2.COLOR_BGR2HSV) v_channel = hsv[:,:,2] # 亮度通道 # 高光像素（亮度 > 220）的比例 highlight_ratio = np.sum(v_channel[product_mask > 0] > 220) highlight_ratio /= np.sum(product_mask > 0) # 亮度方差（反映高光集中度） brightness_std = np.std(v_channel[product_mask > 0]) glossiness = 0.6 * highlight_ratio + 0.4 * (brightness_std / 255) return float(glossiness) def measure_flow_velocity(frame1, frame2, product_mask): """用 Farneback 光流估计质地流动速度""" gray1 = cv2.cvtColor(frame1, cv2.COLOR_BGR2GRAY) gray2 = cv2.cvtColor(frame2, cv2.COLOR_BGR2GRAY) flow = cv2.calcOpticalFlowFarneback(gray1, gray2, None, 0.5, 3, 15, 3, 5, 1.2, 0) magnitude, _ = cv2.cartToPolar(flow[...,0], flow[...,1]) roi_magnitude = magnitude[product_mask > 0] return float(np.mean(roi_magnitude)) # 像素/帧，越高越稀薄

⚠️ 质地评测的基准参考必须来自真实产品的专业实拍视频，而不是品牌的宣传图——后者往往经过修图处理，会引入错误的"黄金标准"。建议在评测集建立之初，专门制作标准参考素材库。

视频一致性

一致性评测：同一视频内的跨帧稳定性

一致性评测是视频评测与图片评测最大的区别所在。图片是单帧，视频是时序。一个在单帧内完美的产品画面，可能在帧与帧之间出现"抖动"——颜色微变、logo 形态漂移、人物面部风格切换——这些在单帧评测中完全察觉不到，却在实际播放时极其明显。

# 帧间产品一致性检测（DINO-v2 特征） from transformers import AutoModel import torch, cv2 from sklearn.metrics.pairwise import cosine_similarity dino = AutoModel.from_pretrained("facebook/dinov2-base") def check_product_consistency(video_path, product_detector): cap = cv2.VideoCapture(video_path) fps = cap.get(cv2.CAP_PROP_FPS) embeddings, timestamps = [], [] frame_idx = 0 while cap.isOpened(): ret, frame = cap.read() if not ret: break if frame_idx % 5 == 0: # 每 5 帧采一次 box = product_detector(frame) if box: crop = frame[box.y1:box.y2, box.x1:box.x2] emb = dino(preprocess(crop)).last_hidden_state.mean(1) embeddings.append(emb.detach().numpy()) timestamps.append(frame_idx / fps) frame_idx += 1 # 计算相邻帧对的余弦相似度 failures = [] for i in range(len(embeddings) - 1): sim = cosine_similarity(embeddings[i], embeddings[i+1])[0][0] if sim < 0.85: # 一致性阈值 failures.append({ "t_start": timestamps[i], "t_end": timestamps[i+1], "similarity": sim }) return failures

跨节点问题

最难追踪的问题：跨节点误差传递

流水线评测中最隐蔽的问题，是上游节点的微小偏差，被下游放大成显著缺陷。一个在创意分析层"听起来不严重"的描述偏差，可能在视频层产生完全不可接受的结果。

误差传递案例：美妆色号偏差的放大链路
输入#216 玫瑰棕
→
创意分析"温柔大地色系"
→
脚本泛化为"自然棕调"
→
分镜"棕色系哑光眼影"
→
视频生成了标准棕色
ΔE=9.3 ✗

真正的问题发生在第 3 步：脚本把精确色号泛化为"自然棕调"，导致分镜丢失了色号信息，最终视频无法还原真实颜色。但如果只看视频节点，你看到的是"颜色还原失败"，而真正的根因在脚本层。

💡 根因分析建议：建立"精确产品属性（色号、规格）的传递追踪"——从输入解析阶段就给关键属性打标记，追踪它们是否在每个下游节点的输出中被忠实保留。这是跨节点误差追踪的最有效手段。

往往埋在脚本里的一个模糊形容词里。

评测实施

这套体系如何在团队中真正跑起来

评测体系设计得再完整，不落地就是零。以下是从评测设计到工程化实施的几个关键判断：

指标的自动化优先级分类
🤖

全自动（Day 1 接入 CI）

违禁词检测、Schema 校验、字数检查、颜色 ΔE、帧间相似度、OCR logo 匹配、ASR 时序对比。规则明确、无需人工。

🤝

半自动（LLM-judge 辅助）

叙事节奏评分、品牌调性一致性、分镜可实现性、受众共鸣度、运镜合理性。LLM 打分 + 低分自动触发人工复核。

👩‍💼

人工（定期抽样）

质地主观感知分、使用场景真实感、购买意愿影响。每周抽 20-30 条人工评审，作为自动指标的校准基准。

触发时机运行的评测层目的
每次 Prompt 变更 文本节点（①②③）自动化指标全跑 快速验证改动无明显退步
