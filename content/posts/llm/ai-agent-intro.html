概念入门

AI Agent：
从"回答问题"到"完成任务"

大语言模型能对话，但不能自主行动。Agent 在 LLM 之上加入了感知、规划与工具调用能力，让 AI 第一次有机会像人一样去完成真实世界中的复杂任务。

2026-05-28 阅读约 12 分钟 Agent · LLM · 工具调用 · 多智能体

当你第一次使用 ChatGPT，它给你的感觉很像一个无所不知的"百科全书"——问什么答什么，逻辑清晰，语言流畅。但你很快会发现它有一个根本局限：它只能"说"，不能"做"。它不能帮你预订机票，不能真正运行你的代码看结果，也不能自主地在网上搜资料再整理成报告。

AI Agent 的出现，正是为了突破这一局限。本文将从概念基础出发，带你梳理 Agent 的核心组件、发展脉络、典型范式，以及当前面临的真实挑战。

基础概念

什么是 AI Agent？

Agent（智能体）这个词来自拉丁语 agere，意思是"行动者"。在 AI 领域，一个 Agent 被定义为：能感知环境、自主做出决策、并通过行动影响环境以实现目标的系统。

这个定义来自 Russell & Norvig 的经典教材《人工智能：现代方法》，早在机器学习崛起之前就已存在。但直到大语言模型（LLM）出现，Agent 才真正获得了足够强大的"大脑"，让这个概念从学术理想走向工程现实。

Agent 的核心感知–决策–行动循环
🌍
环境
输入 / 状态
→ 感知
🧠
LLM 大脑
推理 / 规划
→ 决策
🔧
工具调用
搜索 / 代码 / API
→ 行动
📊
结果 / 反馈
回到环境

这个循环会持续运行，直到 Agent 判断任务已经完成。与单次对话不同，Agent 的工作是一个多步骤、带反馈的迭代过程。

一个最直观的比喻是：普通 LLM 就像一个只会看书的顾问，而 Agent 是能拿起电话、发邮件、打开电脑亲自去办事的助手。

核心组件

Agent 的四大核心组件

一个完整的 AI Agent 系统，通常由以下四个模块构成：

Agent 架构分层
🧠
大脑（LLM）
核心推理引擎，负责理解任务、制定计划、生成行动指令。GPT-4、Claude、Gemini 等都可充当这一角色。
🔧
工具（Tools）
Agent 与外部世界交互的桥梁。包括搜索引擎、代码执行器、数据库查询、API 调用、文件操作、浏览器控制等。
💾
记忆（Memory）
分为短期记忆（当前对话上下文）和长期记忆（向量数据库存储的历史信息）。让 Agent 能记住过去发生的事情。
📋
规划（Planning）
将复杂目标拆解为可执行的子任务序列，并在执行过程中根据反馈动态调整计划。是 Agent 区别于普通 LLM 的关键能力。

这四个模块并非独立运行，而是紧密协作：LLM 看到任务后制定计划，调用工具获取信息，把结果写入记忆，再根据新信息更新计划……如此循环，直到完成目标。

发展历程

从符号 AI 到 LLM Agent：七十年的演进

Agent 并不是 ChatGPT 之后才出现的新概念。这条路已经走了七十年，每一代技术都带来了新的可能，也暴露了新的局限。

Agent 发展时间线
1950s–1980s
符号 AI 与专家系统
以规则和逻辑为核心，STRIPS 规划系统、MYCIN 医疗专家系统等是典型代表。优点是可解释、精确；缺点是知识库维护成本极高，无法应对真实世界的复杂性和不确定性。
1990s–2000s
强化学习 Agent
以 Q-Learning、策略梯度为代表，Agent 通过与环境交互、获取奖励信号来学习行为策略。1997 年 IBM Deep Blue 战胜卡斯帕罗夫，2016 年 AlphaGo 击败李世石，都是这一路线的里程碑。但这类 Agent 只能在定义明确的封闭环境中运作。
2017–2022
Transformer 与预训练语言模型
BERT、GPT 系列的出现让 AI 具备了强大的语言理解和生成能力，但它们本质上仍是"问答系统"，缺乏主动行动的能力。
2023
LLM Agent 元年：ReAct 与 AutoGPT
Google 提出 ReAct（Reasoning + Acting）框架，将 LLM 的推理与工具调用结合；AutoGPT、BabyAGI 等开源项目引发大量关注，让"自主 AI"第一次走入大众视野。OpenAI 正式引入 Function Calling，工具调用有了标准化接口。
2024
多智能体与 Agentic Workflow
Anthropic 提出 Agentic 系统设计原则，吴恩达总结 Agentic Workflow 四大模式；微软 AutoGen、斯坦福 CrewAI 等多智能体框架涌现；OpenAI 发布 Assistants API，工程化落地加速。
2025–至今
Computer Use 与具身 Agent
Anthropic Claude 的 Computer Use 让 Agent 能直接操作桌面；各大厂商 Agent 产品（Devin、Manus、Gemini Deep Research 等）相继落地；Agent 开始与机器人、自动驾驶等物理世界深度融合。

核心范式

三种主流 Agent 范式

当前的 LLM Agent 工程实践中，形成了三种主流的构建范式，各有适用场景：

ReAct：最基础也最常用的单 Agent 范式

ReAct = Reasoning（推理）+ Acting（行动），核心思想是让 LLM 交替输出"思考"和"行动"，形成一个循环：

🤔 思考分析当前情况
→
⚡ 行动调用工具
→
📥 观察获取工具结果
→
🤔 思考根据结果更新判断
→
✅ 结束或继续循环
// 一个典型的 ReAct 轨迹示例 思考: 用户要查询北京明天天气，我需要调用天气工具 行动: weather_api(city="北京", date="tomorrow") 观察: { "temp": "18~26°C", "weather": "多云转晴" } 思考: 已获得天气数据，可以回答用户了 最终答案: 北京明天多云转晴，气温 18-26°C
Plan-and-Execute：先规划再执行

对于复杂任务，ReAct 的逐步决策容易偏离方向。Plan-and-Execute 先用一个"规划器"生成完整任务列表，再逐步执行：

📋 规划阶段
由高能力 LLM（如 GPT-4o）分析目标，生成结构化子任务列表。整体视角更强，不容易在细节中迷失。
⚙️ 执行阶段
每个子任务可交由更小的 LLM 或专用工具完成，效率更高，也更容易并行化处理多个子任务。
多智能体系统（Multi-Agent）

将任务分配给多个专职 Agent，各司其职，通过消息协作完成复杂目标。类比一个软件开发团队：

🏗️
Orchestrator（协调者）
理解整体目标，分解任务，分配给合适的子 Agent，汇总结果。
🔍
Researcher Agent
专注于信息检索，通过搜索引擎、论文数据库等工具收集相关资料。
💻
Coder Agent
专注于代码编写和执行，在沙盒环境中生成、测试、调试代码。
✍️
Writer Agent
将结构化信息整合为自然语言，输出最终的报告、文档或回复。
单个 LLM 再强大，也有上下文长度和推理深度的瓶颈；
多 Agent 协作，让系统突破单一模型的能力边界。

关键机制

让 Agent 变强的四个关键机制

四种核心增强机制对比
机制 作用 典型实现
工具调用 突破 LLM 知识截止日期限制，能获取实时信息、执行真实操作 OpenAI Function Calling、Anthropic Tool Use
RAG 记忆 从外部知识库检索相关文档，补充 LLM 上下文窗口之外的知识 向量数据库 + Embedding 检索（Chroma、Pinecone）
反思与自我修正 让 Agent 评估自己的输出质量，在发现错误时回溯修正，而非盲目执行 Reflexion、Self-Refine 等框架
思维链（CoT） 通过显式推理步骤提升复杂任务的准确率，"让模型先想再答" Chain-of-Thought Prompting、o1/o3 系列模型

工具调用是 Agent 能力的"下限"，决定它能触达什么；记忆和反思是能力的"上限"，决定它能做多复杂的任务。一个成熟的 Agent 系统四者缺一不可。

挑战与局限

Agent 还远未成熟：五大核心挑战

尽管 Agent 赛道热度极高，但工程实践中暴露出的问题也相当棘手。这些挑战直接决定了 Agent 何时能真正可靠地用于生产环境。

🎯
幻觉累积问题
单次 LLM 调用的错误率虽然不高，但 Agent 的多步执行会让错误不断叠加放大，最终导致整个任务失败。
💸
成本与延迟
Agent 完成一个任务可能需要数十次 LLM 调用，推理成本是普通对话的数十倍，响应时间也从秒级变成分钟级。
🔄
无限循环风险
Agent 在遇到歧义或困难时容易陷入循环，反复调用工具却没有进展，既浪费资源又难以检测。
🛡️
安全与权限控制
一个能操作文件、发邮件、调用 API 的 Agent，一旦被恶意提示词注入（Prompt Injection），后果可能是灾难性的。
🔍
可观测性
Agent 的"思考过程"难以追踪，出错了很难定位是哪一步出了问题，调试难度远超传统软件。
📏
长程任务的退化
随着任务步骤增多，Agent 越来越容易忘记原始目标，在某个子任务中"迷失"，偏离最初的用户意图。

Anthropic 工程团队在实践中观察到：Agent 在前几步执行良好，但随着步数增加，性能会快速退化——这在工程上被称为"长 horizon 问题"，是当前 Agent 可靠性最大的瓶颈之一。

现状与展望

Agent 现在能做什么，未来会去哪里？

尽管挑战重重，Agent 在若干"受控场景"下已经展现出切实的生产价值。关键特征是：任务有明确的成功标准、失败有限制（不会造成严重后果）、允许人类介入监督。

当前成熟度矩阵：哪些场景可以用 Agent？
场景 成熟度 代表产品
代码辅助 & 生成 较成熟 GitHub Copilot、Cursor、Devin
信息检索与研究 较成熟 Perplexity、Gemini Deep Research
数据分析与报表 发展中 OpenAI Advanced Data Analysis
客服与工单处理 发展中 Salesforce Einstein、各垂直领域产品

具身机器人控制 早期探索 Figure、1X、Google RT-2

从更长远的视角来看，Agent 技术的演进有三个清晰的方向：

① 更强的推理基础模型——随着 o1、o3、Claude 3.7 Sonnet 等"思考型模型"的出现，LLM 的多步推理能力正在快速提升，这直接改善 Agent 的规划质量。

② 标准化的工具生态——2024 年底 Anthropic 发布的 MCP（Model Context Protocol）协议，试图建立 Agent 与外部工具之间的统一接口，类比 USB 对于硬件生态的意义。

③ 与物理世界的融合——Agent 不会永远停留在数字世界。随着具身 AI 和机器人技术的成熟，"能在真实世界中行动"的 Agent 将成为下一个十年的核心研究方向。

LLM 是 Agent 的大脑，工具是它的手脚，记忆是它的经验，
而"自主完成复杂任务"是它存在的全部意义。

从"回答一个问题"到"完成一项任务"，这不只是功能的叠加，而是 AI 与人类协作模式的根本转变——AI 第一次从工具变成了可以委以任务的"协作者"。
