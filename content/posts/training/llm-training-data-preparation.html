MODEL TRAINING · DATA ENGINEERING 01

大模型训练的数据准备

从 GPT-1 的书籍语料到万亿 token 级预训练，从人工示范到合成指令：数据规模决定模型能够看见多少世界，数据工程决定模型最终学到怎样的世界。

2026-08-22 模型训练 · 第一篇 阅读约 18 分钟 预训练 · 指令微调 · 数据工程 · Scaling Law
导言 · Introduction

大模型的数据准备并不是把网页抓取下来，再送进训练集群。原始文本需要经历来源治理、内容解析、质量过滤、去重、风险处理、数据配比、分词与序列组织等一整套工程流程；进入微调阶段后，问题又会从“文本是否可学”转向“行为是否值得模仿”。

模型参数、训练数据和算力共同构成预训练的三项核心资源。参数量决定模型可以容纳的表示复杂度，数据量提供学习信号，算力决定两者能够发生多少次有效交互。任何一项孤立扩张，都可能遭遇边际收益下降。

数据工程的目标不是最大化 token 数，而是在既定算力与模型规模下，构造信息密度更高、覆盖更合理、来源可追溯、风险可控制的学习分布。
01 · SCALE HISTORY

从 GPT-1 到 Qwen、Kimi：参数和数据共同扩张

2018 年的 GPT-1 已经确立了“先在无标注文本上做生成式预训练，再针对任务微调”的基本范式。当时模型使用 12 层 decoder-only Transformer，参数规模通常记为约 1.17 亿；训练数据是 BooksCorpus 中超过 7,000 本未出版书籍。论文强调这类连续长文本有利于学习长距离依赖。

此后，训练数据从单一书籍语料扩张到经过人工信号筛选的网页，再到大规模 Common Crawl 混合语料；参数规模也从亿级进入千亿级。更重要的变化并非单纯“模型越来越大”，而是业界逐步认识到：更大的模型必须匹配更充分、更高质量的数据。

单位不能直接横比

早期报告常用书籍数量、词数或文件体积，后期论文更多使用 tokenizer 处理后的 token 数。不同 tokenizer 的压缩率、去重强度、训练轮数和序列拼接方式也不同，因此表中的数字用于展示量级演进，不应直接计算为严格的数据效率排名。

进入 MoE 时代后，“参数量”至少有两种口径

总参数量表示模型保存了多少权重，主要影响模型文件体积、显存或内存容量以及专家总容量；激活参数量表示处理一个 token 时实际参与主要计算的参数规模，更接近单 token 训练和推理计算成本。Qwen3-235B-A22B 中的 “235B-A22B”，即 235B 总参数、约 22B 激活参数。

稠密模型每个 token 基本都会经过全部参数，而 MoE 只路由到少数专家。因此，Kimi K2 的 1T 总参数不能直接理解为每个 token 都完成一次 1T 稠密模型计算；另一方面，激活参数也不能完全代表成本，因为注意力层、共享专家、路由、通信与负载均衡仍会产生额外开销。后文的 Chinchilla 比例和 C ≈ 6ND 最初面向稠密 Transformer，迁移到 MoE 时只能作为初步近似。

02 · SCALING LAW

Scaling Law：参数量、数据量与算力的关系

Scaling Law 不是“模型越大越好”的口号，而是用经验关系描述训练损失如何随模型规模、数据规模和计算量变化。Kaplan 等人在 2020 年发现，语言模型交叉熵损失在较大尺度范围内会随参数量、数据量和训练算力呈现平滑的幂律下降。这使团队能够先训练一批小模型，再外推更大训练任务的收益。

早期结论更强调大模型的样本效率，容易形成“优先增加参数、较早停止训练”的计算分配方式。Chinchilla 研究随后重新估计了计算最优边界：在固定训练算力下，模型参数量和训练 token 数应大致同步增长；模型规模翻倍时，训练 token 数也应近似翻倍。

C ≈ 6 × N × D
C训练计算量完成整次预训练所需的浮点运算总数，单位通常为 FLOPs。
N模型参数量稠密模型通常取全部可训练参数；MoE 做粗估时更接近单 token 激活参数。
D训练 token 数训练过程中实际送入模型的 token 次数，包含重复 epoch，不等于唯一文本 token。
系数 6 来自一个常用的工程近似：稠密 Transformer 的前向传播约为每参数、每 token 进行 2 次浮点运算，反向传播约为前向传播的 2 倍，因此一次完整训练约为 2ND + 4ND = 6ND。

这里的 C 是算法层面的 FLOPs，而不是 GPU 标称峰值乘以训练时长。硬件没有被完全利用时，真实耗时会更长；混合精度也会改变每次运算的速度和能耗，但不改变这个量级公式的定义。长上下文注意力、词嵌入、输出层、激活重计算、优化器、跨卡通信和 MoE 路由也没有被系数 6 完整表达。

因此，C ≈ 6ND 适合在训练规划早期比较数量级。例如在稠密模型中，参数量翻倍且 token 数不变，训练 FLOPs 约翻倍；参数量与 token 数同时翻倍，训练 FLOPs 约变为四倍。进入实际集群预算阶段，仍需使用具体架构的 FLOPs 统计和集群吞吐实测。

“每个参数约 20 个 token”不是固定定律

Chinchilla 的 70B 参数与 1.4T token 恰好约为每参数 20 token，因此该比例经常被当作工程经验。但它依赖论文中的模型族、数据分布、训练目标和计算预算。Llama 3 的小模型甚至被刻意训练得远超计算最优点，因为在相同推理成本下，更充分训练的小模型可能具有更好的部署价值。

实际决策还需同时考虑推理成本、数据是否稀缺、是否允许重复训练、目标能力分布和模型生命周期。Scaling Law 提供预算配置的起点，而不是替代数据实验的终点。

03 · DATA SOURCES

预训练数据来自哪里

通用大模型需要覆盖事实知识、自然语言表达、逻辑推理、代码结构、多语言与不同文本形态。单一来源即使质量很高，也无法提供足够广泛的学习分布。现代训练集通常由多个数据域组成，并为不同域设置不同的采样权重。

WEB

公开网页

覆盖面最大，包含新闻、知识页面、博客、论坛和长尾主题；同时混杂模板、广告、SEO 内容、机器生成文本与大量重复。

BOOKS · PAPERS

书籍与学术资料

长篇结构完整，论述密度较高，适合学习长距离依赖和专业表达；授权、版式解析和领域偏差需要单独治理。

REFERENCE

百科与高质量知识库

事实组织清晰、引用结构稳定，常被用作高质量参考域；主题覆盖受编辑机制影响，不能替代广泛网页数据。

CODE · MATH

代码、数学与推理语料

提供形式化结构、可验证答案与过程性推理信号。解析器、许可证、自动生成代码和重复仓库会显著影响质量。

DIALOGUE

论坛、问答与对话

包含真实问题、口语表达和多轮互动模式，适合补充任务形态；答案正确性、隐私与社区风格差异是主要风险。

MULTILINGUAL

多语言与区域数据

决定跨语言迁移与非英语能力。低资源语言容易被语言识别误判，也更容易在统一质量分类器中被过度过滤。

04 · PRETRAINING PIPELINE

从原始文档到训练 token：清洗与处理流水线

预训练数据工程通常分为“进入数据湖”和“进入训练批次”两条边界。前者关注来源、解析与治理，后者关注混合比例、tokenizer、序列长度和采样。只有保留数据血缘与版本信息，后续才可能解释模型行为或撤回问题来源。

RAW DATA → TRAINING SEQUENCES
获取与登记来源、时间、许可、哈希、数据血缘
解析与规范化正文提取、编码修复、语言识别、结构保留
过滤与去重质量、安全、隐私、重复、污染检测
混合与分词域权重、tokenize、packing、训练切分
  1. 来源治理：记录抓取时间、来源域、使用许可、删除机制和内容哈希。涉及用户数据时，需要最小化采集并完成隐私与合规评审。
  2. 正文解析：从 HTML、PDF、代码仓库等载体中提取有效内容，去除导航、Cookie 提示和广告，同时保留代码缩进、公式、标题等有意义的结构。
  3. 语言识别与编码修复：修复乱码、异常 Unicode、空白与控制符，再做文档级或段落级语言识别。多语言混排不宜被简单判为噪声。
  4. 质量过滤：结合长度、符号比例、重复 n-gram 等规则，以及 fastText、RoBERTa 或大模型蒸馏的质量分类器。规则负责高精度剔除，模型负责识别更隐蔽的低质模式。
  5. 多粒度去重：URL 级消除重复抓取，文档级 MinHash 等方法处理近似副本，段落或行级去除模板与跨站转载。去重还能降低训练集与验证集交叉污染。
  6. 安全、隐私与敏感信息处理：识别高密度个人身份信息、成人内容、恶意代码、凭据和其他不适合进入训练集的内容。过滤策略应可审计，并评估对特定语言或群体的误伤。
  7. 基准污染检查：对评测题、答案及其改写做精确和模糊匹配。训练语料包含公开基准并不等于能力提升，可能只是让评估失去解释力。
  8. 数据混合：按来源质量、能力目标与实验结果设定权重，而非按原始数据体积等比例采样。GPT-3 已经对高质量数据进行更高频采样；DoReMi 等工作进一步尝试用代理模型优化域权重。
  9. 分词与序列组织：确定 tokenizer 后再统计真实 token 预算；将短文档拼接为训练序列时保留文档边界，避免跨文档注意力产生无意义关联。
清洗并非越强越好

过度过滤会把口语、方言、低资源语言、少数群体表达和长尾知识一起删除，使语料看上去更“整洁”，却降低真实世界覆盖。每条过滤规则都应在抽样集上测量精确率、召回率及群体差异。

05 · DATA REQUIREMENTS

高质量预训练数据需要满足什么条件

高质量不等同于书面化，也不等同于单一分类器给出的高分。对通用模型而言，数据质量是信息密度、正确性、覆盖范围、分布平衡、可追溯性与风险约束的组合。

01

多样性

覆盖语言、领域、文体、难度、长度和任务形态，保留足够的长尾知识与不同表达方式。

02

信息密度与可读性

正文完整、结构连贯、噪声较少，避免模板堆叠、关键词填充、自动翻译残片和无意义重复。

03

正确性与可验证性

专业、代码和数学数据应提高事实与过程可靠性；可执行代码、证明或引用信息能提供额外验证信号。

04

分布平衡

防止网页中的娱乐、营销等高频类别淹没低频但高价值领域。多样性需要通过采样权重真正进入训练批次。

05

低重复与低污染

减少对热门文本的机械记忆，保持验证集和基准的独立性，并抑制重复数据造成的梯度偏置。

06

可追溯与可撤回

能够定位来源、版本与处理规则，在许可、隐私或质量问题出现后支持定向删除和重新构建。

Llama 3 的公开报告提供了一个具体例子：最终数据混合约有 50% 通用知识、25% 数学与推理、17% 代码、8% 多语言 token。该比例不是通用配方，而是结合知识分类、缩放实验和目标评测得到的项目选择。数据配比本身就是训练超参数。

06 · SFT DATA

微调数据与预训练数据的本质差异

预训练让模型学习“文本世界如何延续”，指令微调让模型学习“面对请求应当如何行动”。前者追求广泛覆盖，后者强调行为示范的准确性、一致性和任务分布。错误的预训练文档只占海量 token 中很小一部分；错误的高权重指令样本则可能直接塑造模型行为。

MINIMUM INSTRUCTION RECORD
System / Context角色、约束、背景材料、工具定义
Instruction任务目标、输入、格式与成功条件
Response可学习的目标答案、推理结果或动作轨迹
Metadata来源、领域、难度、语言、质检与版本

InstructGPT 的数据流程展示了经典路径：从标注员编写的提示和真实 API 提示中取样，收集人工示范用于监督微调；再让人工对多个模型输出排序，用于后续偏好建模。这里的核心不是“把问答写成 JSON”，而是先定义希望模型学习的行为，再让数据结构承载这些行为。

07 · INSTRUCTION SOURCES

微调指令从哪里获得

HUMAN

人工编写与专家示范

最适合高风险、专业和复杂任务，能够精确定义正确行为；成本高，标注者之间的一致性需要培训与仲裁。

PRODUCT

真实产品请求

能够反映真实语言和需求分布。进入训练前必须完成授权、去标识化、敏感信息处理，并过滤低质量反馈和攻击内容。

TASK CONVERSION

公开任务与知识库改写

将分类、抽取、问答和知识文档转成统一指令格式，答案通常更容易验证；模板化表达可能限制语言多样性。

SYNTHETIC

模型合成与 Self-Instruct

从少量种子任务扩展指令、输入和输出，并过滤无效或相似样本。适合扩大覆盖，但会继承教师模型的偏差与错误。

DISTILLATION

强模型蒸馏

利用更强模型生成答案、评语、工具轨迹或修订版本，再经验证器和人工抽检进入训练；需要防止能力坍缩为单一教师风格。

TOOLS · MULTI-TURN

工具调用与多轮轨迹

记录参数选择、执行结果、错误恢复和上下文状态。不能只保留最终答案，否则模型难以学习何时调用以及如何处理工具反馈。

LIMA 使用 1,000 条精心筛选的提示—回答对展示了质量与多样性的价值：750 条来自高质量社区内容，250 条由人工编写；消融结果表明，仅增加数量而不增加提示多样性会迅速出现收益递减。该结论不意味着所有微调都只需要 1,000 条数据，而是说明数据规模必须与基础模型能力、任务难度和覆盖目标共同讨论。

08 · SFT CLEANING

指令数据的清洗逻辑

指令数据清洗应围绕“模型是否值得模仿这条行为”展开。文本通顺只是最低门槛，任务定义、答案正确性、约束遵循、拒答边界和整体分布都需要单独检查。

  1. 结构有效：角色字段合法、轮次顺序正确、工具调用闭合、输入与输出不为空，模板和特殊 token 与训练格式一致。
  2. 指令清晰：任务目标可识别，必要上下文完整，不存在无法判断的指代、互相冲突的约束或被截断的附件。
  3. 答案正确：事实、计算、代码和引用尽可能由规则、执行器、检索或专家复核。对开放任务，至少验证是否满足任务要求。
  4. 行为合适：答案应当相关、完整、克制，符合安全与隐私要求；拒绝样本需要展示正确边界，而非机械拒绝所有敏感词。
  5. 去重与近似去重：同时检查指令、答案和任务语义。仅替换人名或数字的模板样本可能造成某类行为权重虚高。
  6. 避免泄漏：去除评测集、内部保留集和包含标准答案痕迹的数据，防止用测试题训练再用同一测试题证明提升。
  7. 风格不过度统一：响应可以遵循共同质量规范，但仍应覆盖简短回答、长文、表格、代码、结构化输出和自然对话等合理形态。
  8. 模型筛选与人工抽检结合：大模型适合做初筛、打标和成对比较，关键能力与高风险样本仍需人工验收。评审模型与生成模型同源时，要特别警惕共同偏差。
09 · DISTRIBUTION DESIGN

指令分布如何设计

微调集不是请求日志的简单缩小版。原始流量会把高频、简单、重复问题放大，却无法保证复杂推理、错误恢复、长上下文、安全边界等关键能力有足够样本。目标分布应从产品任务、能力地图和风险模型反推。

能力
问答、写作、抽取、推理、代码、工具、规划、拒答
设最低覆盖与上限
领域
通用知识、专业域、业务私域、长尾主题
按目标价值加权
难度
直接回答、多约束、组合任务、开放问题、不可回答
避免简单样本淹没

单轮、多轮、长上下文、工具反馈、纠错与澄清
与真实链路匹配

分布设计可以采用“基础覆盖 + 目标加权 + 难例回流”三层结构。基础覆盖保证通用能力不被遗忘；目标加权提升核心业务能力；线上失败、对抗测试和评测误差再形成难例池，定期进入新版本数据。

10 · PRODUCTION RECIPE

一条可执行的数据生产流程

定义能力与风险分类

先列出目标任务、禁止行为、关键边界和验收指标，再确定需要哪些数据，而不是从现有数据反推目标。

建立来源池与统一数据协议

区分人工、产品、公开任务和合成数据，统一消息、工具、来源、许可、质量等级与版本字段。

分层生成与验证

低风险任务可由模型批量生成并自动验证；专业和高风险任务提高专家参与度，并保留完整审阅记录。

去重后再统计分布

在语义去重完成后重算能力、领域、长度、难度与语言占比，否则大量模板副本会制造虚假的覆盖感。

小规模训练与消融

先用小模型或短周期训练比较数据版本，做来源、过滤器和混合权重消融，确认提升来自数据而非评测波动。

建立评测—数据闭环

将模型失败映射回能力分类，形成难例、修订样本和回归集；训练集与保留评测集始终隔离。

发布数据卡与版本清单

记录来源构成、过滤逻辑、已知偏差、删除记录、数据哈希和适用范围，使训练结果能够复现与审计。

11 · EVALUATION

如何判断数据准备是否有效

数据指标只能说明流水线发生了什么，模型指标才能说明模型学到了什么。两类指标需要对应起来：例如近似重复率下降后，应观察验证损失、记忆率和基准污染是否改善；增加代码数据后，应同时检查代码能力、通用语言能力和安全表现。

  • 数据层：有效 token 数、各域占比、语言占比、精确与近似重复率、过滤通过率、PII 命中率、来源覆盖和删除可追溯率。
  • 训练层：分域验证损失、梯度异常、样本利用率、长序列比例、训练稳定性，以及不同数据混合下的 Scaling Law 外推误差。
  • 能力层：知识、推理、代码、多语言、长上下文、工具调用、指令遵循和业务任务的独立评测。
  • 行为层：事实可靠性、约束遵循、安全边界、拒答质量、风格稳定性和人工偏好。

最有解释力的方法通常是受控消融：固定模型、算力与训练配置，只替换一个数据版本或一项过滤策略。若多个因素同时变化，即使总分提高，也很难知道下一轮应当继续扩大什么、修复什么。

12 · PITFALLS

常见误区

数据越多越好

重复、错误和低信息密度 token 同样消耗算力，并可能放大偏差。有效数据量比磁盘体积更有意义。

20 token / 参数是固定配方

该比例来自特定实验条件。部署成本、重复数据、模型结构和目标任务都会改变最优训练点。

合成数据可以无限自举

没有人工种子、外部验证与多教师约束时，错误、措辞和偏好会在迭代中被持续放大。

清洗等于删除“不规范”文本

真实输入包含口语、拼写错误和混合语言。只保留整齐文本会削弱模型对真实环境的鲁棒性。

训练集分布等于线上流量分布

线上高频问题会挤压关键长尾与安全样本。训练分布必须体现目标能力和风险，而不只是请求次数。

评测集公开就可以混入训练

基准污染会让分数失去泛化含义。公开可见不代表适合作为训练数据。
