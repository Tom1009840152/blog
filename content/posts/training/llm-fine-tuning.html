MODEL TRAINING · FINE-TUNING 02

大模型微调：全参数微调与高效参数微调

微调不是简单地“再训练几轮”。它是一项受数据分布、更新范围、算力预算和评测体系共同约束的模型工程：先明确要改变什么，再决定更新多少参数，最后用可复现的证据判断变化是否有效。

2026-08-22 模型训练 · 第二篇 阅读约 20 分钟 全参数微调 · PEFT · LoRA · 模型评估
导言 · Introduction

预训练让模型获得广泛的语言、知识与推理能力，微调则改变这些能力被调用的方式。它可以让模型遵循指令、适应专业任务、稳定输出结构或对齐偏好，但也可能带来过拟合、通用能力回退和安全边界漂移。微调的核心问题因此不是“是否使用 LoRA”，而是目标、数据、更新范围与评估是否形成闭环。

工程讨论中常把 SFT、DPO、全参数微调和 LoRA 放在同一层比较，实际上它们属于不同维度。SFT 与 DPO 描述用什么数据和目标函数训练；全参数微调与 PEFT 描述哪些参数允许更新。SFT 可以采用全参数微调，也可以采用 LoRA；DPO 同样可以更新全部参数，或只训练适配器。

可靠的微调方案应回答四个问题：目标行为是什么，样本如何代表目标分布，哪些参数需要更新，以及模型变化如何被观测、评估和纠正。
01 · TWO AXES

先分清两个维度：训练目标与参数范围

监督微调（SFT）使用输入—理想输出样本，通过语言模型损失提高理想回答的条件概率，适合学习指令遵循、任务流程、输出格式和示范中的表达模式。偏好优化使用成对偏好或奖励信号，强调“多个可行回答中哪一个更好”。DPO 将偏好学习转化为相对简洁的分类式目标，不需要先训练奖励模型再运行 PPO。

参数范围是另一条轴：全参数微调允许基座模型的全部权重参与梯度更新；PEFT 则冻结绝大部分基座参数，只训练新增或选定的少量参数。两条轴组合后，才构成完整训练方案。

02 · FULL FINE-TUNING

全参数微调：最大的更新自由度

全参数微调在反向传播时为模型的全部可训练权重计算梯度，并由优化器更新。若模型有 N 个参数，就需要管理相应规模的权重、梯度和优化器状态；采用 Adam 类优化器时，优化器状态往往是训练显存的重要组成部分。参数分片、混合精度、激活重计算、FSDP 或 ZeRO 可以降低单卡压力，但不会消除总计算与通信成本。

优势

  • 表达能力上限高：模型的注意力、前馈网络、归一化与嵌入等权重都可协同适应目标分布，适合分布变化大、数据充分且性能上限优先的场景。
  • 部署路径直接：训练结果本身就是完整模型，不需要在推理时加载外部适配器，也不存在适配器与基座版本错配。
  • 研究控制更完整：层级学习率、冻结策略、持续预训练与多阶段训练可以在统一权重空间内设计。

代价与风险

  • 资源成本高：梯度、优化器状态和分布式通信随模型规模扩张；同等基座上的多个任务通常还要分别保存完整检查点。
  • 更新更容易扩散：目标数据过窄、学习率过高或训练时间过长时，通用能力和安全行为可能回退。全参数更新并不自动等于更高质量。
  • 迭代治理更重：每次实验都产生大体积产物，版本回滚、评估、复制和部署成本高于小型适配器。
03 · PEFT

高效参数微调：冻结基座，只训练必要增量

PEFT（Parameter-Efficient Fine-Tuning）是一组方法的统称，而不是单一算法。共同思想是保留预训练权重，只训练新增模块、软提示或少量缩放参数。它减少了可训练参数、梯度与优化器状态，因此通常显著降低训练内存和检查点体积；基座模型也可以复用给多个任务。

REPARAMETERIZATION

LoRA

冻结原权重，将更新量表示为两个低秩矩阵的乘积。训练变量少、生态成熟，权重可合并回基座，通常是生成式大模型 PEFT 的首选起点。

QUANTIZED BASE

QLoRA

以 4-bit 保存冻结基座，梯度经过量化基座传回 LoRA。NF4、双重量化与分页优化器进一步控制内存，适合显存受限的实验。

ADDITIVE MODULE

Adapter

在 Transformer 层中插入小型瓶颈网络。任务隔离清晰，但未合并时会增加额外计算路径；适配器结构与部署框架需要一致。

PROMPT / RESCALING

Prefix、Prompt 与 IA³

前两者学习连续软提示或前缀状态；IA³ 学习缩放 key、value 与前馈激活的向量。参数量更小，但复杂任务的容量与稳定性依赖模型和目标。

LoRA 的低秩更新

设预训练线性层权重为 W₀ ∈ Rᵈ×ᵏ。全参数微调直接学习与 W₀ 同形状的更新；LoRA 假设任务更新具有较低的内在秩，用两个小矩阵表示增量：

W′ = W₀ + ΔW，  ΔW = (α / r) · B A
W₀ 保持冻结；A ∈ Rʳ×ᵏ 与 B ∈ Rᵈ×ʳ 可训练；r 是低秩维度，决定适配器容量和参数量；α 控制更新的缩放。提高 r 会增加容量与显存，但并不保证单调提升。

LoRA 原论文在 GPT-3 175B 的特定配置下，报告相对 Adam 全参数微调可将可训练参数减少约 10,000 倍、GPU 内存需求降低约 3 倍。这是论文实验条件下的结果，不是所有模型与 target modules 的固定比例。实际可训练参数量取决于 rank、目标层数量、矩阵形状以及是否训练 bias、embedding 或输出头。

QLoRA 不是“4-bit 全参数训练”

QLoRA 将预训练模型以 4-bit 量化形式放入显存，基座权重保持冻结；反向传播只更新 LoRA 参数。原论文借助 NF4、双重量化与分页优化器，使 65B 模型能够在单张 48GB GPU 上微调，并在其评测条件下保持与 16-bit 全参数微调相当的任务表现。

QLoRA 的主要优势是训练内存，而非自动提高质量。量化算子、硬件支持、计算数据类型和长上下文激活仍会影响速度与显存；当训练资源充足或任务对数值误差敏感时，应通过同数据、同评测的 LoRA 与 QLoRA 对照实验决定。

选择原则

默认可从 LoRA 建立低成本基线：若目标能力达到验收线，继续扩大训练范围没有必要；若在数据质量、训练步数和 rank 消融后仍出现稳定的容量瓶颈，再比较更广 target modules、较高 rank 与全参数微调。QLoRA 解决的是基座驻留显存，不应被当作一种独立的任务目标。

04 · SAMPLE SCHEMA

需要构造怎样的微调样本

SFT 样本应把产品要求转化为可学习的输入—输出关系。一个可靠样本不仅包含问题和答案，还应保留系统约束、上下文、工具状态、来源、能力标签、难度与质量信息。元数据通常不直接进入模型上下文，但决定后续如何切分、配比、审计和分析。

CONVERSATIONAL SFT SAMPLE · JSONL
{
  "messages": [
    {"role": "system",    "content": "遵守客服政策，只依据给定订单信息回答。"},
    {"role": "user",      "content": "列车停运后如何退款？"},
    {"role": "assistant", "content": "……经过审核的目标回答……"}
  ],
  "task": "refund_policy",        // 能力单元
  "difficulty": "hard",             // 难度与边界类型
  "source_id": "policy_2026_08_v3", // 来源与版本
  "quality": "expert_verified",   // 审核状态
  "split_group": "policy_refund"    // 防泄漏分组
}

样本至少覆盖五类行为

  • 典型任务：线上最常见输入与标准流程，保证主要价值路径有足够覆盖。
  • 表达变化：口语、省略、错别字、多轮追问、长上下文和不同语言，避免模型只识别模板。
  • 边界与反例：信息不足、前提冲突、越权请求、不可执行任务与需要澄清的输入。
  • 结构化输出：JSON、函数调用、引用、表格或固定字段必须以可自动校验的样本呈现。
  • 安全与拒答：不仅示范何时拒绝，还要示范合理解释、允许范围和替代路径。

损失应落在真正需要学习的 token 上

对话式 SFT 通常只对 assistant 消息计算损失，system 与 user 消息作为条件而非预测目标。Hugging Face TRL 的 assistant_only_loss 即用于这一设置，但依赖 chat template 正确标记生成区间。若模板与损失掩码错误，模型可能学习复述用户问题、预测控制 token，或把 padding 纳入损失。

训练前应抽样解码 tokenized 数据，逐项检查 BOS/EOS、角色边界、截断位置、label mask 与多轮消息。许多“模型学不会格式”的问题，根源并不在学习率，而在训练样本实际进入模型后的序列与预期不一致。

05 · DATA VOLUME

需要多少数据：没有脱离任务的固定答案

样本数量必须与基座能力、目标跨度、样本长度、质量、覆盖和训练目标同时解释。1,000 条高质量通用示范可能足以让强基座改变回答风格，却不足以覆盖一个包含数百种工具与规则的业务系统；百万条低质量模板也可能只让模型更稳定地复制错误。

公开工作数据规模说明了什么不能推出什么
LIMA · 20231,000 组精心筛选的提示—回答强基座已有大量知识时，少量高质量、多样化示范可以有效塑造回答行为与格式。不能推出复杂领域、弱基座或大规模工具系统都只需要 1,000 条。
Self-Instruct · 2023从人工种子任务出发，由模型生成并过滤大规模指令数据合成数据可以扩展任务多样性；无效、相似样本过滤是方法的核心环节。不能推出未经验证的自生成回答可直接作为可靠监督。
FLAN Collection · 2023大规模任务、模板和 zero/few-shot/CoT 混合任务平衡、混合提示设置与数据富化会显著影响跨任务泛化。不能只依据总样本数解释效果，任务构成和混合权重同样关键。
DeepSeek LLM · 2024超过 100 万条多来源 SFT 实例广覆盖聊天模型会进入百万级数据工程，并需要策略与数据消融。不能把百万条视为单一窄任务的最低门槛。
QLoRA · 2023跨 8 个指令数据集训练 1,000 多个模型论文发现小型高质量数据也可取得很强结果，数据质量对聊天评测影响突出。不能证明量化、LoRA 或某一数据量在所有任务上无损。

用能力单元估算第一版，而不是先拍一个总数

先将目标拆成“能力 × 场景 × 难度 × 输出形式 × 风险”的能力单元，再为每个单元准备具有表达变化和边界覆盖的样本。第一版数据预算可以写成：

样本预算 ≈ 能力单元数 × 每单元有效变体数
这是一种工程估算，不是 Scaling Law。有效变体必须改变问题表达、上下文组合、推理路径或边界条件；仅替换实体名称的模板复制不等于新的覆盖。

若任务分类有 40 个能力单元，每个单元先构造 25 个经过审核的有效变体，第一版就是约 1,000 条。这个数字的意义是建立可分析的覆盖基线，而不是宣称 1,000 条足够上线。高风险或长尾单元应分配更多样本，简单格式转换可以更少。

固定基座、训练方法、token 预算口径和评测集，按数据子集递增训练。若 2× 到 4× 的目标收益已趋平，而通用能力回退或训练成本继续增加，应停止盲目扩量，转向错误分桶、质量修订或改变模型容量。

样本数还会掩盖长度差异，因此应同时记录有效训练 token、assistant 目标 token 和各任务的 token 占比。短分类回答与长篇推理各有 10,000 条时，提供的监督量与梯度贡献并不相同；按样本均匀混合也不等于按 token 均匀混合。

06 · DATA QUALITY

数据构建、清洗与切分

微调数据的质量不是单一分数，而是正确性、相关性、可学性、多样性、安全性与可追溯性的组合。构建流程应先定义验收规则，再进入生产与清洗。

  1. 定义能力分类和失败标准。明确需要提升的行为、不可接受的回答、自动指标与人工判断标准。
  2. 汇集人工、产品、公开与合成来源。保留来源版本、许可、生成模型和审核记录，避免数据脱离治理。
  3. 规则与模型联合清洗。删除空答案、格式错误、语言错配、明显幻觉、相互矛盾指令和不可验证的伪引用。
  4. 精确与语义去重。模板近重复会放大高频措辞并造成评测泄漏；去重后重新统计任务与 token 分布。
  5. 先分组切分，再做增强。按文档来源、用户、实体、规则版本或时间切分训练、验证和测试，不能让同源改写落入不同集合。
  6. 建立难例与回归集。线上失败、专家争议和关键边界进入独立集合，版本之间持续复测。

数据分布不应简单复制线上流量。高频简单问题会压低长尾、风险与复杂任务的权重；训练集需要在真实流量、业务价值和失败成本之间重新配比。FLAN 的研究也表明，任务平衡与不同提示设置的混合是指令微调效果的重要组成部分。

07 · TRAINING OBSERVABILITY

训练中需要观测什么

训练损失只是最基础的信号。微调过程至少需要同时观测优化稳定性、数据利用、验证泛化、目标能力与通用能力，否则一次“loss 正常下降”的训练仍可能得到不可用模型。

优化信号

train / validation loss、learning rate、gradient norm、梯度溢出、被跳过的 step、权重或 LoRA 更新范数。

用于发现发散、过拟合、异常批次和更新过强。

数据与 token

有效 batch token、assistant 目标 token、截断率、padding 比例、序列长度、各任务与来源的 token 占比。

用于确认训练实际看到的数据与设计分布一致。

系统效率

tokens / s、step time、GPU 利用率、显存峰值、通信时间、数据加载等待和 checkpoint 时间。

用于区分模型问题与数据、内核或分布式系统瓶颈。

在线评测

固定间隔保存 checkpoint，运行小型目标集、格式校验、通用能力 canary 与安全回归。

用于及早发现“目标上升、整体退化”，并选择最佳 checkpoint。

不要只看 epoch，要看有效更新量

同样是 3 个 epoch，样本长度、packing、梯度累积和 batch size 不同，优化器 step 与目标 token 数可能相差很大。实验记录至少应包含：基座与 tokenizer 版本、数据哈希、chat template、最大长度、有效 batch token、总 step、学习率曲线、随机种子、精度与量化设置、PEFT 配置以及评测代码版本。

LoRA 实验还应记录 r、lora_alpha、dropout、target modules、是否训练 bias、是否使用 rsLoRA，以及最终是否 merge。缺少这些信息时，同名“LoRA 微调”之间无法可靠比较。

08 · EVALUATION

评估体系：证明提升，也证明没有破坏

微调评估必须保留基座模型作为对照，并在相同解码参数、prompt template 和运行环境下比较。只报告微调后分数无法判断提升来自训练、提示变化还是评测波动。

评估层核心问题典型方法判断重点
目标任务预定能力是否真正提升准确率、F1、执行成功率、结构校验、专家评分按能力单元、难度、长度与来源分桶，不能只看总均值
通用回归原有知识、推理、代码、多语言是否退化固定公共基准 + 自有 canary 集与基座同配置比较，关注显著回退而非只看目标增益

评测集必须与训练数据隔离

随机按行切分对模板数据尤其危险：同一原文的不同问法、同一用户会话的相邻轮次、同一规则的轻微改写可能同时进入训练集和测试集。更可靠的方法是按来源文档、实体、会话、时间或任务簇分组切分，并在合成与增强前确定 split。

自动基准适合重复回归，但开放式生成还需要人工或模型裁判。模型裁判应使用固定 rubric、盲化候选顺序并用人工子集校准；教师模型同时生成训练答案又担任唯一裁判时，评测容易偏向教师风格。EleutherAI 的 lm-evaluation-harness 可统一公共与自定义任务的配置和结果记录，但业务成功标准仍需单独定义。

09 · DIAGNOSIS

从训练现象反推问题，并进行调整

调参应从可复现的现象开始。先按能力、来源、长度、难度和风险分桶，再判断问题来自数据、优化、容量还是评测。直接提高 rank、epoch 或学习率，往往只会放大尚未定位的问题。

超参数调整的顺序

  1. 先确认数据与模板。错误标签、切分泄漏和 loss mask 问题不能通过调参修复。
  2. 再寻找稳定学习率与训练长度。全参数微调通常需要比 LoRA 更保守的更新；具体数值取决于模型、batch token 和数据分布，必须通过小规模网格或逐级实验确定。
  3. 随后调整容量。LoRA 先比较 target modules，再比较 rank 与 alpha。rank 增加会提高参数量，但容量不足必须由分桶评测证实。
  4. 最后优化效率。在质量基线稳定后再引入 packing、长序列、量化、分布式策略与吞吐优化，避免系统变量掩盖模型变量。

实验应遵循单变量原则：固定数据版本和评测集，每次只改变一个主要因素。至少运行关键配置的多个随机种子，报告均值、波动与失败样本，而不是只选择最高单次分数。

11 · PITFALLS

常见误区

LoRA 等于 SFT

LoRA 是参数更新方式，SFT 是训练目标。LoRA 同样可以用于偏好优化，SFT 也可以更新全部参数。

rank 越高越好

更高 rank 提供更多容量，也增加参数与过拟合空间。应以受控消融和错误分桶判断是否需要。

QLoRA 就是 4-bit 全参训练

QLoRA 的量化基座保持冻结，真正更新的是 LoRA 参数；其核心价值是降低训练内存。

训练 loss 越低，模型越好

低损失可能来自模板记忆、重复数据或泄漏。模型质量必须由独立任务、回归、安全和人工评估共同证明。

数据越多越保险

重复和错误样本会持续贡献梯度。覆盖、正确性、配比与边界样本通常比原始条数更重要。

SFT 能替代知识库

SFT 不提供事实可追溯性，也不适合频繁更新的知识。RAG、工具和继续预训练各自解决不同问题。

随机切分就能防泄漏

同源改写、相邻会话和模板变体会跨集合泄漏。应在增强前按来源、实体、时间或任务簇分组。

只测目标任务即可

微调可能以通用能力、安全和服务性能为代价。没有基座对照与回归集，就无法计算真实净收益。
