GENERATIVE VISUAL LANGUAGE · INTENT TO PROMPT

从视觉意图到提示词：
生成影像的描述语法

提示词不是形容词的堆叠，也不是某个模型的秘密口令。它更接近一份压缩后的视觉创作简报：说明要表达什么、画面里发生什么、观众从哪里观看，以及哪些条件不能被改变。

导言 · Introduction

“孤独、电影感、高级、梦幻”表达的是创作愿望，却不是完整的画面说明。模型还需要知道：谁在何处，正在做什么，主体与环境怎样排列，光从哪里来，镜头是否移动，最终结果又要用于什么。提示词写作的核心，正是把不可见的意图翻译成可观察、可生成、可检查的视觉条件。

自然语言可以启动生成，但它不会像程序代码那样确定每一个像素。模型会把文本、参考图和参数转化为生成条件，再在训练所得的视觉分布中寻找一种可能结果。相同提示词可能得到不同构图；不同模型也可能以不同方式理解同一组词。

因此，提示词能力不是记忆一张“万能词表”，而是建立一种翻译能力：先辨认视觉意图，再把意图拆成画面变量，最后用清晰的语言组织这些变量。输出不符合预期时，还要能判断究竟是主体、关系、构图、风格还是时间运动出了问题。

好的提示词不负责把想象完整搬进模型，而是把最重要的创作决定变成模型可利用的条件，也把成败标准变成创作者可以逐项检查的问题。
01 · CONDITION, NOT CODE

提示词是一组生成条件，不是确定性代码

图像生成模型并非先理解一句话，再按名词清单逐一绘制。文本通常会被编码成内部表征，与图像生成过程共同作用。Google 的 Imagen 研究发现，扩大预训练语言模型对图文一致性的改善，超过单纯扩大图像生成网络的收益，说明语言理解对文本生成图像十分关键。相关研究同时使用包含空间关系、数量、属性和长文本的 DrawBench 来检验模型，而不是只检查画面是否“好看”。参见 Google Research：Imagen。

OpenAI 的 DALL·E 3 研究则从训练数据的描述质量入手：使用更详细的合成图像说明进行训练，提高模型对文本的遵循能力。但论文也明确指出，空间关系、计数等问题并未因此彻底解决。参见 Improving Image Generation with Better Captions。

一个重要边界 · Probabilistic Output

提示词更像“给生成分布加条件”，而不是“向渲染器提交完整场景文件”。它可以提高某类结果出现的概率，却不能保证每个属性、文字、手势或镜头参数都被精确执行。需要高一致性、高可复现或像素级准确时，还要结合参考图、编辑、遮罩、分镜、后期排版与人工验收。

02 · THREE-LAYER TRANSLATION

先做三层翻译：意图、画面与执行

直接从“想表达什么”跳到“输入什么词”，中间缺少了画面设计。稳定的方法是分三层思考。第一层定义沟通目的，第二层把目的变成可见证据，第三层补充交付与约束。三层之间不是同义改写，而是逐步减少歧义。

LAYER 01

意图层：为什么生成

定义作品要传递的核心判断，以及它服务于什么场景。

  • 用途与受众
  • 情绪与叙事
  • 信息优先级
  • 观看后的预期感受
LAYER 02

画面层：看见什么

为抽象意图寻找可观察的视觉证据。

  • 主体、动作与关系
  • 环境、构图与视点
  • 光线、色彩与材质
  • 运动、节奏与变化
LAYER 03

执行层：怎样交付

说明模型入口、画幅、参考素材与不可改变项。

  • 图像或视频及用途
  • 画幅与时长
  • 参考图各自职责
  • 保留项与排除项

例如，意图“让一款户外水壶显得可靠”仍然不可见。进入画面层后，可以变成：壶体落有细密水珠，硬质涂层没有明显划痕，戴手套的手牢固握住把手，背景是低温清晨的山脊，低角度近景强调结构，冷灰环境中保留一处暖色识别色。进入执行层后，再补充横版广告图、主体右置、左侧保留文案空间、商标形态必须保留等条件。

03 · A STABLE GRAMMAR

建立稳定语法：从主体到约束

不同模型没有统一的提示词语法，但视觉描述可以保持稳定。OpenAI 的官方图像提示指南建议按一致顺序组织背景与场景、主体、关键细节和约束，并说明预期用途；Google 的 Imagen 指南把主体、背景或情境、风格作为清晰的起点。两者共同指向一个实用原则：先交代画面的骨架，再添加真正影响结果的细节。参见 OpenAI：GPT Image Prompting Guide 与 Google Cloud：Imagen 提示词指南。

交付物 ＋ 主体 ＋ 动作与关系 ＋ 环境
＋ 构图与视点 ＋ 光线与色彩 ＋ 媒介与材质 ＋ 约束

这是一张检查清单，不是必须逐项填满的公式。某项不影响创作判断时，可以省略；两个条件互相冲突时，应先确定优先级。

01 · DELIVERABLE

交付物与用途

电影静帧、商品主图、概念设计、分镜草图或 8 秒单镜头。用途会改变构图密度、留白和完成度。

02 · SUBJECT

主体与识别属性

主体数量、年龄段、服装、形态、材质和独特标志。优先保留能区分对象的属性。

03 · ACTION

动作、状态与关系

正在做什么、看向哪里、与何物接触、谁遮挡谁。动词通常比情绪形容词更能组织场景。

04 · SETTING

环境与时空

地点、时间、天气、季节、空间尺度和背景活动。环境为主体提供因果与氛围。

05 · COMPOSITION

构图、景别与视点

全景或近景，平视或俯拍，主体位于何处，前中后景怎样分层，哪里需要留白。

06 · LIGHT & COLOR

光线与色彩

光源方向、软硬、光比、色温、主辅色和饱和度。描述光如何塑造物体，而不只是写“氛围光”。

07 · MEDIUM

媒介、风格与材质

摄影、版画、3D、拼贴或手绘；表面是粗糙、透明、镜面还是纤维。媒介决定画面如何被制造。

08 · CONSTRAINT

保留项与排除项

必须保留的人物、产品形态、镜头方向和版式空间，以及不能出现的文字、对象或视觉干扰。

信息顺序主要服务于维护。OpenAI 的指南明确指出，提示词可以是短句、段落、带标签的分区，甚至接近 JSON 的结构；关键在于意图和约束清楚，生产模板容易复用，而不是寻找某种神奇标点。

04 · MAKE ABSTRACT VISIBLE

把抽象形容词翻译成可见证据

“高级”“电影感”“治愈”不是错误词语，但它们覆盖的视觉可能性过多。更可靠的做法是先保留意图词，再补充一组能让这种感受成立的观察条件。以下映射不是固定词典，而是创作假设；题材、文化语境和传播目的改变后，映射也要调整。

抽象意图可观察的画面变量需要避免的误解
高级克制的综合色数；清洁留白；高光受控；材质边缘清晰；信息层级少而明确。并不等于全黑、金色、豪华酒店或无限降低饱和度。
电影感明确景别与机位；有动机的光源；前后景分离；环境中的空气感；统一的色彩方向。单独添加 cinematic、胶片颗粒或宽银幕比例，不能自动形成叙事。
梦幻柔和逆光；低反差亮部；薄雾或半透明前景；浅景深；缓慢、连续的环境运动。发光、星尘、粉紫色同时堆叠，可能遮蔽主体与空间结构。
紧张受限画框；硬侧光或局部高反差；倾斜方向；稀少警示色；急促或不稳定运动。高饱和红色只是一个信号，不足以单独建立紧张关系。
极简单一视觉焦点；有限色彩；干净轮廓；大面积负空间；表面细节受到控制。极简不是“没有设计”，仍需精确决定比例、位置与材质。

翻译时可以连续追问三次：这种感受从哪一种空间关系产生？由哪一种光色与材质支持？观众通过怎样的视点和时间节奏体验它？回答越能落到可观察现象，提示词越容易被诊断。

05 · BIND ATTRIBUTES

明确属性归属：谁是什么，谁在何处

多主体场景的困难不只是“模型漏掉了词”，还包括属性绑定错误。T2I-CompBench 将组合能力拆为颜色、形状、纹理等属性绑定，空间与非空间关系，以及更复杂的组合。测试中的典型问题是：对象都出现了，但颜色、材质或位置分配给了错误对象。参见 NeurIPS 2023 论文 T2I-CompBench。

AMBIGUOUS
“一只红色和蓝色的杯子与书，放在桌面上。”

颜色可能属于杯子、书或两者；数量、左右位置和遮挡关系也没有确定。

BOUND
“左侧是一只哑光红色陶瓷杯；右侧是一本钴蓝色硬壳书。杯子压住书的左下角，两者都完整可辨。”

属性紧跟对象，并使用左右、压住、完整可辨等关系词减少歧义。

绑定关系的四个写法

属性靠近名词：不要把所有颜色、材质集中放在句尾。对象分句描述：每个主要对象先形成独立单元。关系使用具体介词和动词：左侧、背后、悬挂于、遮挡、握住，比“在一起”更明确。数量与可见范围同时说明：“三只完整可见的玻璃杯”比“几只杯子”更容易验收，但计数仍是模型常见弱项。

复杂度预算 · Complexity Budget

每增加一个主体、属性、空间关系或动作，组合难度都在上升。关键对象过多时，优先拆成多次生成、局部编辑或分层合成，而不是继续加长句子。语言更精确可以降低歧义，却不能消除模型能力边界。

06 · LENGTH AND MODEL DIFFERENCES

提示词多长合适：没有跨模型的唯一答案

不同产品对文本的处理、参数入口和默认美学不同。Midjourney 的官方基础指南认为，短而简单的提示词通常更有效；细节越少，变化空间越大，控制力也越低。OpenAI 的图像指南则支持更结构化的生产简报，强调用途、构图、约束和小步迭代。二者并不矛盾：一个更靠近探索，一个更靠近控制。参见 Midjourney：Prompt Basics。

短提示：扩大探索只定义主体、情境和一种视觉方向，适合寻找意外构图与风格。
中等描述：建立方向加入动作、关系、构图、光色，适合多数单幅图像任务。
结构化简报：加强控制加入交付用途、明确约束、参考职责和验收条件，适合连续迭代与团队协作。

更实用的判断标准不是字数，而是最短但不丢失关键约束：某条描述如果能减少重要歧义，就保留；如果只是同义词叠加，或模型已有参数单独控制，就删除。先用最小可行提示词生成基线，再根据输出缺陷增加信息，通常比一次写满所有细节更容易定位问题。

07 · IMAGE EXAMPLE

完整示例：把“雨夜等待的孤独”写成画面

原始意图只有一句：“一个人在雨夜等车，很孤独，很有电影感。”它已经提供主体、环境和情绪，但缺少观看位置、人物行为、环境关系与光线来源。先不急于添加更多风格词，而是把孤独翻译成空间与动作：人物独自站在候车亭边缘，周围有大量空位；他不看镜头，只看向尚未到来的车；冷色雨幕包围人物，远处车辆只留下模糊暖色光。

IMAGE BRIEF16:9 · REALISTIC FILM STILL
交付物：一张 16:9 的现实主义电影静帧，用于短片情绪提案。

主体：一名穿深灰长外套的成年人独自站在公交候车亭右侧边缘，双手收在衣袋里，微微缩肩，侧脸看向画面左侧的空路。

环境与关系：深夜小雨，候车亭其余座位完全空着；湿润路面延伸到左侧远处，背景没有可辨认的人群。

构图与视点：中远景，平视机位，人物位于右三分之一，左侧保留大面积负空间；亭柱形成前景框架，人物与远处道路有明显层次。

光线与色彩：候车亭顶部冷白荧光灯作为主光，人物面部处于微弱侧光；远处一辆未入画车辆留下柔和琥珀色散景，整体低饱和蓝灰。

质感：自然雨丝、潮湿织物、受控高光、细微空气雾感，不过度磨皮，不过量胶片颗粒。

验收约束：只出现一名完整可辨的人物；不看镜头；不出现文字、水印、雨伞；左侧负空间保持干净。

这份提示词没有声称某个精确焦距一定会被物理还原，而是说明中远景、平视、人物位置、前景框架和空间层次。OpenAI 的官方指南也提醒，详细相机规格可能被宽松理解，更适合用来表达整体观感与构图，而不能当作精确光学模拟。

不要一次改完所有问题

如果结果“太热闹”，第一轮只减少背景人物与广告牌；如果“孤独感仍然不足”，第二轮只扩大左侧负空间或缩小人物比例；如果“像棚拍”，第三轮再调整主光动机与路面反射。每轮只改变一个主变量，才能知道哪项描述真正影响了结果。

08 · ADD TIME FOR VIDEO

从图像到视频：在画面语法上增加时间

视频提示词不仅要描述“这一帧长什么样”，还要说明状态如何变化。Google 的 Veo 指南将场景、运镜、镜头与光学效果、视觉风格和时间元素分别说明；Adobe Firefly 的官方指南给出“景别＋角色＋动作＋地点＋美学”的简洁结构，并强调使用具体动作、运镜和节奏。参见 Google Cloud：Veo 视频提示词指南 与 Adobe Firefly：视频提示词指南。

初始状态＋主体动作＋相机运动＋环境运动＋节奏与演化＋结束状态

服装、人物身份、光线方向、天气和空间方位等贯穿镜头的条件，需要单独列为连续性约束。模型对时间段和运镜词的执行程度会随产品、模式与素材而变化，时间轴应被视为清晰意图，而不是逐帧保证。

8-SECOND SINGLE SHOT · 雨夜候车
0–2 SEC建立空间中远景静止起镜。人物在候车亭右侧，左侧道路空旷，雨丝稳定落下。
2–6 SEC动作与推进相机非常缓慢地向前推近。人物听到远处车辆声后抬头，暖色车灯反射从左向右扫过湿地。
6–8 SEC形成结束状态停在中景。车辆没有进入画面，人物轻微失望地垂下视线，仍位于右侧。

一个镜头只保留一个主运镜

“推近、环绕、俯冲、快速摇摄、再突然拉远”同时出现，容易形成互相竞争的指令。短视频先确定一种主运镜，再把主体动作和环境变化放进同一空间逻辑。多次视点变化更适合拆成多个镜头，用分镜分别生成。

09 · REFERENCES AND EDITS

参考图不是万能答案：先说明每张图控制什么

参考图可以承担不同职责：内容参考决定对象，身份参考保持人物，构图参考规定空间布局，风格参考提供材质与色彩方向。多张参考图混用时，若没有说明各自角色，模型可能同时复制不需要的内容，或把风格误当成构图。

CONTENT

内容参考

“使用图 A 的产品形态与标签位置，不继承背景、光线和手部姿势。”

IDENTITY

身份参考

“保持图 B 的面部身份与发型，服装改为深灰外套，表情转为克制。”

COMPOSITION

构图参考

“只采用图 C 的右侧主体和左侧留白关系，不复制其建筑或人物。”

STYLE

风格参考

“借用图 D 的低饱和色彩、潮湿高光与空气雾感，不复制具体对象。”

编辑任务还要把“改什么”和“保留什么”分开。OpenAI 的官方指南建议用类似“只改变 X”的指令，并列出应保持不变的内容。与其写“把背景换成海边”，更稳定的表达是：“只把室内背景替换为阴天海岸；保持人物身份、姿势、服装、画面裁切和主光方向不变；新增背景与人物边缘的光色要自然一致。”

10 · DIAGNOSE THE OUTPUT

输出不对时，先诊断问题属于哪一层

有效迭代不是在原提示词末尾继续添加“更准确、更专业、更完美”，而是比较目标与输出，找出偏差所在。GenEval 把文本生成图像的对象共现、数量、颜色与位置分别评估，说明“总体相似”不足以判断提示词遵循。参见 GenEval：An Object-Focused Framework for Evaluating Text-to-Image Alignment。

主体缺失或数量错误

减少竞争对象；把关键对象提前；写明数量与完整可见；复杂场景改为分层生成或局部编辑。

颜色、材质互换

让属性紧跟对象；每个对象单独成句；补充左右、前后、遮挡等关系；删除含混并列词。

构图位置错误

同时说明景别、主体画面位置与留白用途；使用“左三分之一”等相对关系，不依赖抽象的“平衡构图”。

风格吞没了内容

先固定主体和构图，再添加一种主要媒介或风格方向；删除同义风格词堆叠，明确参考图只控制什么。

光线没有动机

指出主光源的位置与性质，说明它照亮主体哪一侧，以及环境中哪种反射或实景光支持它。

视频动作或运镜冲突

一个镜头只保留一个主运镜；用时间顺序写主体动作；减少同时发生、方向相反或无法连续完成的事件。

人物或物体持续漂移

重申身份、服装、材质、光向等不变量；缩短镜头；使用参考图、首尾帧、遮罩或产品提供的一致性工具。

01定义验收生成前列出 3–5 个必须满足的可见条件。
02生成基线先用最小提示词观察模型默认理解与变化范围。
03单变量修改每轮只处理一个主要偏差，保留可比较性。
04记录版本保存模型、模式、参数、参考图、提示词和结果。
11 · COMMON PITFALLS

六个常见误区：语言精确不等于结果必然精确

把提示词写成形容词串

词很多但关系很少，模型只得到模糊风格方向。先补主体、动作、空间与光源。

迷信固定顺序和标点

结构的价值在于减少遗漏、便于维护，并非逗号、括号或权重符号具有跨模型通用含义。

堆叠摄影参数

焦距、光圈和胶片型号可以表达观感，但模型未必进行严格光学模拟。优先描述画面效果。

同时要求相反结果

“极简但信息丰富”“静止同时高速运动”需要明确主次，或拆分为不同版本与镜头。

只写不要什么

排除项要与正向目标配套。先说明理想画面，再删除最可能破坏结果的少量元素。

把一次好结果当成方法

偶然样本无法证明提示词稳定。用多次生成、单变量对照和验收表检验可复现性。

精确文字、品牌标识、复杂手部交互、多人身份一致、严格产品结构和长镜头连续性，仍然需要重点复核。涉及公开传播或商业交付时，还要检查肖像、版权、商标、素材授权、误导性内容与所用平台的政策；提示词方法不能替代合规判断。

12 · PRACTICE

五个练习：把词汇积累变成视觉判断

一种意图，三种视觉翻译

选择“安静”或“压迫”等意图，分别用空间、光色、视点三种路径各写一版提示词。比较它们是否产生不同但成立的画面。

属性绑定压力测试

设置两个对象、两种颜色、两种材质和一个遮挡关系。先写含混版本，再写分句绑定版本，每版生成多张并记录错误类型。

单变量迭代

固定主体、环境和风格，只改变主体在画面中的大小；再恢复原设置，只改变主光方向。训练辨认每个变量的视觉作用。

静态描述改为时间描述

把一张静态画面扩展为 6–8 秒单镜头，写清初始状态、一个主体动作、一个主运镜和结束状态，避免加入第二场景。

反向描述与删减

选择一张构图清晰的参考图，按主体、关系、构图、光色、媒介重新描述；随后逐项删除，判断哪些信息真正决定了图像识别。

建议记录 · Prompt Notebook

每次练习保存意图、模型与模式、参考素材、完整提示词、关键参数、输出缩略图、问题分类和下一轮只改变的变量。提示词库若只有“成功文本”而没有上下文与失败记录，很难迁移到另一题材或另一模型。
